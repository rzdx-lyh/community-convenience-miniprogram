## 二、协作流水线（链式，非独立）

```
用户 → PM 拆解方案 → 产品 PRD → UI 设计预览 ──用户同意──> 架构师：接口契约+任务卡
                                                              ├─> 前端（并行）
                                                              └─> 后端（并行）
   前后端联调 → 合并 main → 测试 ──通过──> 运维部署上线 → PM 终审打包提交
                        ↑不通过（打回修复后回归）┘
```

- 每个 skill 开工前**必须先输出自己的调查问卷**，等用户回答后才动手。
- 下游读上游落盘的文件续作（`docs/`、`contracts/`），不重复生成。
- 用户闸门 G1 拆解 → G2 PRD → G3 设计 → G4 契约任务卡 → G5 测试通过 → G6 上线提交，每道闸门由用户说"同意"后项目经理放行。

## 三、Git 分支策略（多人协同）

| 分支 | 用途 | 规则 |
| --- | --- | --- |
| `main` | 主分支（稳定可演示） | 受保护；只接受联调通过后的合并；合并后打 tag（v1.0.1） |
| `feature/frontend` | 前端开发分支 | 仅前端工程师提交 |
| `feature/backend` | 后端开发分支 | 仅后端工程师提交 |

合并顺序：两 feature 分支并行开发 → 联调 → 合并 main → 测试 → 打 tag → 部署。

## 四、使用方式（DSH Agent Teams / 多人协同）

1. 以本目录为团队工作区；`00-总提示词.md` 的内容作为团队任务输入。
2. 9 个成员 agent 各加载对应 skill 文件作为角色设定；**只有收到上游交付物才开工**。
3. 每个 skill 先问问卷 → 用户答 → 才产出；产出全部写盘，供下游读取。
4. 每个 skill 可用电脑工具自由搜索/读写/执行命令（工具清单见各 skill「可调用工具」）。
