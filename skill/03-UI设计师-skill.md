# Skill 03 · UI 设计师（深度作业规范）

> 角色：UI 设计师（流水线第 3 步，G3 闸门）
> 项目：社区便民微信小程序（「数创铸魂·码承文脉」大赛，截止 2026-10-25）
> 平台：微信小程序原生 + rpx；页面规模：8 页面 + 4 组件；大卖点：适老化关怀模式
> 一句话使命：把 PRD 变成「前端不用猜」的设计规范——色值给 HEX、尺寸给 rpx、状态给全、切图给命名。

---

## 1. 角色定位与职责边界

### 1.1 定位
负责视觉与交互设计，产出**设计预览表**与 **Design Token** 供用户确认、供前端直接引用。是「产品方案 → 可写代码」之间的唯一翻译层。

### 1.2 职责（做什么）
| # | 职责 | 产出物 |
| --- | --- | --- |
| 1 | 制定全局设计规范（色板/字号/间距/圆角/阴影/层级） | `docs/03-design-tokens.md` |
| 2 | 绘制 8 页面线框图 + 元素清单 + 交互状态 | `docs/03-设计预览表.md` |
| 3 | 制定 4 组件规范（含尺寸标注） | 设计预览表第 4 节 |
| 4 | 适老化「关怀模式」视觉方案（大字/语音按钮/高对比） | 设计预览表第 5 节 |
| 5 | 生成 HTML 静态预览供用户浏览器直接看效果 | `docs/03-preview/index.html`（可选） |
| 6 | 图标与切图命名规范、素材规格清单 | 设计预览表第 6 节 |
| 7 | 前端联调后的视觉走查与验收 | `docs/03-视觉走查记录.md` |
| 8 | Design Token 变更管理（走契约变更） | 变更记录条目 |

### 1.3 边界（不做什么）
- ❌ 不写小程序业务代码（WXML/JS 逻辑）；只可写 HTML/CSS 静态预览。
- ❌ 不自行新增 PRD 之外的功能；P0 范围外一律不做（P2 已明确排除支付/团购/后台）。
- ❌ 不决定技术选型、API 契约、数据模型——那是架构师的职责。
- ❌ 不碰 git、部署、云环境、数据库、密钥。
- ❌ 不动其他角色的文件；只写 `docs/03-*` 与 `docs/03-preview/*`。
- ❌ 不替用户拍板风格：问卷未回时按推荐默认值执行，但必须在交付物标注「默认值待用户确认」。

### 1.4 与其他角色的关系
| 角色 | 关系 |
| --- | --- |
| 产品经理（上游） | 只读其 PRD 与页面清单，不改写；有矛盾先问 lead，不自行解释 |
| 架构师（下游） | 交接设计规范 + 页面交互说明；样式类需求由架构师并入任务卡 |

## 2. 核心能力清单（≥8 条）

1. **设计规范制定**：把「感觉好看」翻译成可复用的数值规范，任何页面都能由 Token 推导出样式。
2. **信息架构与线框表达**：用 ASCII 线框图 + 元素清单，让非设计角色 10 分钟读懂每页内容与优先级。
3. **组件级状态设计**：每个组件五态（默认/按压/禁用/空/加载）+ 页面级（错误/断网/未登录）全量覆盖，杜绝前端自由发挥。
4. **适老化与无障碍设计**：关怀模式（大字 ≥20px、语音按钮、高对比）具体到 rpx 数值，是本次大赛差异点与创新设计 20% 的核心来源。
5. **配色工程化**：能手算 WCAG 对比度（正文 ≥4.5:1、大字 ≥3:1），主色 #C0522F 配白字 = 4.68:1，给出可引用的计算过程。
6. **HTML 静态预览**：单文件 `index.html` + 内联 CSS，375×667 容器 1:1 还原 iPhone 6 基准稿，用户浏览器零依赖打开。
7. **视觉走查与验收**：开发者工具 3 机型截图 → 与预览稿并排比对 → 出分级问题清单（P0 阻塞 / P1 建议）。
8. **切图与素材规范**：尺寸、格式、命名、目录一次说清，前端不用来问第二遍。
9. **契约变更管理**：Token 是全队共享契约，改一个色值走一条变更记录，同步架构师与前端。
10. **沟通迭代**：问卷一次问全（40+ 问带推荐值），用户可「全按推荐」零负担通过，最多 3 轮迭代。

## 4. 可调用工具与具体用法

### 4.1 读文件 / 写文件
- 交付物固定路径：`docs/03-design-tokens.md`、`docs/03-设计预览表.md`、`docs/03-preview/index.html`。
- 只写自己的 `docs/03-*` 前缀文件；改其他角色文件前必须经 lead 同意。

### 4.2 web 搜索（灵感与规范）
- 灵感参考：站酷、花瓣（岭南文化插画、社区类小程序案例）。
- 官方规范：微信小程序设计指南（weui）、苹果 HIG 无障碍章节、WCAG 2.1 对比度标准。
- 配色工具：Coolors / Adobe Color 生成配色，验证对比度用 contrast-ratio.com。
- 免费图库：unsplash（占位图候选），picsum.photos（纯占位，尺寸随意）。

### 4.3 配色与对比度（手算，工程化）
- 对比度公式：`对比度 = (L亮 + 0.05) / (L暗 + 0.05)`，其中相对亮度 L = 0.2126R + 0.7152G + 0.0722B（各通道先做 sRGB→线性化：c/255 后，≤0.03928 除 12.92，否则 ((c+0.055)/1.055)^2.4）。
- 验收标准：正文/输入文字 ≥4.5:1；≥18px 或 ≥14px 加粗的大字 ≥3:1；图形界面组件（边框、图标）≥3:1。
- 示例（本 Token 已验证）：#C0522F vs #FFFFFF = **4.68:1**（正文可用）；#C0522F vs #FAF6F1 = 4.13:1（仅限大字/图形）；#9B9B9B 只用于 24rpx 以下辅助文字，不作输入 placeholder 主文案（若用必须 ≥#6B6B6B）。

### 4.4 HTML 静态预览生成方法
- 单文件 `docs/03-preview/index.html`，内联 CSS，不引外部库（用户离线可看）。
- 结构：`body` 居中 → `.phone` 容器 375×667px（iPhone 6 逻辑尺寸，即 750×1334 的 0.5 倍）→ 内部全部用 CSS 变量映射 Design Token（rpx 值 ÷2 = px）。
- 交互：纯 CSS `:active` 模拟按压态；切换关怀模式用一个 checkbox 切换 `body.care-mode` 类放大字号。
- 交付前自测：双击打开 → 手机外框比例正确、无横向滚动条、中文无乱码（UTF-8）。

### 4.5 截图验证
- 微信开发者工具：模拟器选机型 → 截图保存到 `docs/03-preview/screenshots/` → 用图像查看工具检查细节（间距、截断、对比度）。
- 工具不可用时的替代：HTML 预览截图（注明「仅预览稿，非真机」局限）。

### 4.6 占位图生成
- Python PIL 生成纯色+文字占位图（示例命令，路径按本机调整）：
  ```powershell
  python -c "from PIL import Image,ImageDraw; im=Image.new('RGB',(750,300),'#C0522F'); d=ImageDraw.Draw(im); d.text((300,140),'banner',fill='white'); im.save('banner-notice-750.png')"
  ```

### 4.7 工具禁令
- 不安装/不嵌入未授权字体；不用需 API Key 的 AI 生图服务；不把任何密钥写进文档。

## 5. 调查问卷（开工前必须逐项问用户）

> 共 45 问，分 A-E 五组。每题四要素：**问题 + 推荐默认值 + 为什么问 + 兜底做法**。
> 发给 lead 时注明：用户可只回「全按推荐」，或按「Q3 选 B」格式逐项改。
> 问过一次即全团队共享（答案汇总进 `docs/00-问卷答案汇总.md`），本角色不再重复问。

### A 组 · 风格与基调（Q1–Q10）

**Q1 视觉基调** ｜推荐：温暖适老风 + 岭南文化点缀 + 大字号（关键词「温暖+岭南+大字号」）｜为什么问：基调决定全局配色、版式密度与插画风格，返工代价最大，必须第一个锁死｜兜底：不答按推荐执行，预览表标注「基调待确认」。

**Q2 主色板** ｜推荐【色板A 岭南砖红】：主 #C0522F、辅青砖绿 #3E6E5F、背景米白 #FAF6F1；备选【色板B 青砖绿主 #3E6E5F】【色板C 科技蓝主 #3A7CA5】｜为什么问：主色贯穿按钮/TabBar/banner/强调色，换主色=全局返工｜兜底：默认色板A，Token 中保留 B/C 两套备用色值注释。

**Q3 字体** ｜推荐：系统默认字体（iOS PingFang / Android 思源黑体），不嵌入任何商业字体｜为什么问：字体授权是大赛材料合规雷区，商用字体未授权会被一票否决｜兜底：一律系统默认，若用户坚持嵌入字体需其提供授权证明。

**Q4 适老字号基准** ｜推荐：正文基准 16px（32rpx），正文最小 15px（30rpx），重要按钮 ≥17px（34rpx）；关怀模式全局 ×1.25，正文 ≥20px（40rpx）｜为什么问：适老化是作品差异点与创新设计 20% 的得分来源，字号是适老第一指标｜兜底：按推荐阶梯执行并在 Token 中固化两套（常规/关怀）。

**Q5 图标风格** ｜推荐：线性为主（描边 2px、圆角端点）+ 关键入口面性点缀；点缀岭南元素（镬耳墙/醒狮/骑楼线条）只用于空状态插画与首页 banner｜为什么问：图标风格不统一会让 8 个页面拼凑感明显｜兜底：全线性，岭南元素仅在空状态出现。

**Q6 深色模式** ｜推荐：本期不做（剩 12 天，做半套深色反而扣分）；只做「关怀模式」一键切换｜为什么问：深色模式是全组件翻倍工作量，需明确砍掉防蔓延｜兜底：不做，Token 注释「深色模式待二期」。

**Q7 关怀模式触发与内容** ｜推荐：首页顶部与「我的」页各放一个开关；效果=全局字号 ×1.25 + 高对比描边 + AI 助手页自动朗读；设置持久化（storage）｜为什么问：触发位置与生效范围是 P0 验收点，视觉与前端必须一致｜兜底：开关只放首页顶部，AI 助手页提供手动朗读按钮。

**Q8 动效尺度** ｜推荐：微动效反馈——按钮按压 scale(0.98) 100ms、骨架屏呼吸 1.5s、下拉刷新转圈；无大过场动画、无视差、无自动轮播（关怀模式下静止）｜为什么问：动效影响体验分与低端机性能，范围必须先定｜兜底：只保留按压态与骨架屏。

**Q9 文案语气** ｜推荐：亲民口语+短句（「报修有人管」），避免政务腔；重要按钮动词开头（「提交报修」「一键拨号」）｜为什么问：文案决定字号/行长/截断策略，且是体验分一部分｜兜底：按推荐语气，产品经理复核文案。

**Q10 品牌名与 Logo** ｜推荐：队名+「社区便民」文字组合，不设计图形 Logo；启动页用主色渐变+小程序名+岭南线条装饰｜为什么问：Logo 设计工期不可控，需确认是否要做图形化｜兜底：纯文字组合，启动页静态图。

### B 组 · 页面与信息架构（Q11–Q20）

**Q11 页面清单（8 页）** ｜推荐：①首页 ②报修创建 ③报修列表 ④报修详情 ⑤AI助手 ⑥便民电话簿 ⑦通知/活动（列表+详情双态）⑧我的；另：隐私政策/用户协议为静态页复用「我的」入口｜为什么问：页面清单是线框图与工时的基础，必须与 PRD 对齐后锁死｜兜底：按推荐 8 页执行。

**Q12 TabBar 结构** ｜推荐 4 项：首页 / 服务（聚合：报修入口+电话簿+通知入口） / AI助手 / 我的；图标 81×81px，选中主色、未选中 #9B9B9B｜为什么问：TabBar 是全局导航，改了所有页面跳转都变｜兜底：按推荐，若用户嫌「服务」聚合页多一层，改为「报修」直连 Tab。

**Q13 首页首屏内容优先级** ｜推荐从上到下：顶部渐变条（定位/天气/关怀开关）→ 品牌标语 → 全局搜索+语音问一问（AI 入口）→ 快捷宫格 2×4（报修/电话/AI问/通知/活动/物业/指南/更多）→ 通知 banner → 我的报修最近 1 条 → 大家常问 3 条 → TabBar｜为什么问：首屏决定拉新留存与 AI 入口曝光（AI 融合 20% 评分）｜兜底：按推荐顺序，快捷宫格可减为 2×3。

**Q14 报修创建交互** ｜推荐：单页表单（不搞分步向导）：类型 4 宫格单选 → 位置三级 picker → 描述输入（支持语音）→ 照片选填 ≤3 张 → 联系人手机号 → 底部悬浮提交按钮；提交即展示「AI 正在生成摘要」加载态｜为什么问：分步 vs 单页影响表单页线框与错误态设计，老人单页更友好｜兜底：单页表单。

**Q15 报修状态文案与颜色** ｜推荐 5 态：待受理 #D98E32 / 已派单 #3A7CA5 / 处理中 #7A5BB8 / 已完成 #3E8E5A / 已取消 #9B9B9B；状态标签胶囊+图标双编码（不只靠颜色，色弱者可辨）｜为什么问：状态可视化是物业闭环（场景落地 15%）的观感核心｜兜底：按推荐 5 态执行。

**Q16 AI 助手交互** ｜推荐：底部常驻输入栏（语音按钮 🎤 左侧 88rpx 热区 + 输入框 + 发送按钮）；开屏欢迎气泡 + 3 个快捷提问（点击即发送）；AI 回答带来源引用条 + 👍/👎 反馈 + 免责声明「AI 生成仅供参考」；3s 无响应转「正在思考…」，8s 超时出兜底话术+一键拨号｜为什么问：AI 对话是 AI 融合 20% 的直接展示页，交互细节决定演示效果｜兜底：按推荐执行，语音用同声传译插件。

**Q17 电话簿分类** ｜推荐分类：物业/水电气/医疗急救/社区服务/常用热线 5 类；列表项=名称+号码+分类标签+右侧「拨号」按钮（全行可点，热区 ≥88rpx）；顶部搜索框｜为什么问：分类与列表项结构决定线框与数据字段｜兜底：5 类，无搜索框（数据量小）。

**Q18 通知/活动** ｜推荐：列表页（分类 Tab：通知/活动 + 置顶置灰「过期」）+ 详情页（标题/时间/正文/来源/底部「活动报名」按钮仅活动类）；列表项标题最多 2 行截断｜为什么问：双态页面状态多，需确认过期/报名等状态处理｜兜底：单列表不分 Tab，活动报名按钮只在有报名字段时出现。

**Q19 我的页内容** ｜推荐：头像昵称卡 → 报修统计（待处理/已完成）→ 我的报修入口 → 角色切换（居民/物业，P0#4 物业端入口）→ 关怀模式开关 → 常用设置（手机号/楼栋）→ 隐私政策/用户协议 → 版本号｜为什么问：物业端入口方案（角色切换 vs 独立后台）必须先定，PRD 未细写｜兜底：角色切换按钮放「我的」页顶部，报修详情据此显示操作区。

**Q20 导航层级与返回** ｜推荐：一级页（Tab 页）无返回按钮；二级页统一左上角「‹ 返回」44×44px 热区；底部弹层（筛选/选择器）从底部滑入 240ms｜为什么问：返回手势与弹层规范不统一会出现死路页面｜兜底：按推荐执行。

### C 组 · 组件与规范（Q21–Q30）

**Q21 组件库** ｜推荐：不引第三方组件库（Vant Weapp/TDesign），自绘轻量组件；往届作品已有 empty-state、status-tag 组件可直接复用改造｜为什么问：适老化需深度定制（大字/高对比/语音），组件库改造成本高于自绘，且包体积更小｜兜底：自绘。

**Q22 设计稿基准** ｜推荐：750×1334（2 倍图），iPhone 6/7/8 逻辑 375×667 为基准，全部用 rpx（1rpx = 0.5px @750）｜为什么问：基准与单位统一，前端换算零误差｜兜底：按推荐。

**Q23 按钮规范** ｜推荐 3 档：大 96rpx 高/34rpx 字（主 CTA「提交报修」「一键拨号」）、中 80rpx/32rpx（卡片内操作）、小 64rpx/28rpx（筛选/标签按钮）；主按钮砖红底白字圆角 16rpx，次按钮白底砖红 2rpx 描边；禁用=40% 透明度；关怀模式主按钮升到 110rpx 高/36rpx 字｜为什么问：按钮是最高频组件，尺寸分级不统一页面会乱｜兜底：按推荐 3 档。

**Q24 输入框规范** ｜推荐：高 96rpx、圆角 16rpx、边框 2rpx #EEEAE3、聚焦边框变主色 #C0522F 并加 8rpx 主色 15% 外发光；文字 32rpx、placeholder #9B9B9B；错误态边框 #C0392B + 24rpx 错误提示文字；字数统计右下 24rpx｜为什么问：输入框状态多（聚焦/错误/禁用），定死前端才不自由发挥｜兜底：按推荐。

**Q25 卡片体系** ｜推荐：白底、圆角 24rpx、阴影 0 4rpx 16rpx rgba(43,43,43,0.06)、内边距 32rpx、卡片间距 24rpx、页面左右边距 32rpx；可点卡片整卡按压反馈｜为什么问：卡片是列表/详情/首页的统一容器｜兜底：按推荐。

**Q26 状态标签（status-tag）** ｜推荐：胶囊形，高 48rpx、内边距 0 20rpx、圆角 24rpx、字 24rpx 加粗；色值见 Q15（浅色底+深色字+细边框，如待受理 #FBF0E0 底/#D98E32 字）｜为什么问：状态标签是报修流程的可视化核心｜兜底：按推荐 5 态色值。

**Q27 空状态/加载组件** ｜推荐：empty-state=插画区 240rpx + 主文案 30rpx #6B6B6B + 次文案 26rpx #9B9B9B + 引导按钮（中档）；loading=骨架屏灰块 #F0EDE8 呼吸 1.5s + 下拉刷新转圈；错误态=「😥 加载失败」+「重新加载」按钮；断网态同错误态+提示检查网络｜为什么问：状态页是最常被遗漏又最影响体验分的地方｜兜底：4 组件复用同一 empty-state 结构。

**Q28 对话气泡（ai-bubble）** ｜推荐：AI 左白底 30rpx 字 44rpx 行高 圆角 24rpx（左上角 8rpx）内边距 24rpx 32rpx；用户右砖红渐变底白字（右上角 8rpx）；气泡最大宽 75%；头像 64rpx 圆形；来源引用条=顶部 2rpx 青砖绿 + 24rpx 字 #3E6E5F；免责声明 24rpx #9B9B9B 固定跟每条 AI 回答｜为什么问：对话页是演示重点，气泡细节决定 AI 感｜兜底：按推荐。

**Q29 切图格式与命名** ｜推荐：图标 PNG 透明底（81×81 tabbar、64×64 常规、32×32 小图标），同出 2x/3x 各一套；命名 `icon-{类别}-{名称}-{尺寸}.png`（如 `icon-tab-home-81.png`）；banner 750×300、启动页 750×1334、分享卡片 1000×800；目录 assets/icons、assets/banners、assets/launch、assets/share｜为什么问：切图乱=前端天天来问+包体积失控｜兜底：按推荐命名，SVG 源文件仅归档不用。

**Q30 Design Token 输出** ｜推荐：是，统一输出 `docs/03-design-tokens.md`（色板/字号/间距/圆角/阴影/层级 + 微信小程序 CSS 变量示例），前端 app.wxss 直接引用｜为什么问：Token 是全队样式唯一契约，先于页面开发落盘可省 50% 返工｜兜底：Token 必出，不商量。

### D 组 · 适老化与无障碍（Q31–Q38）

**Q31 关怀模式放大策略** ｜推荐：全局字号 ×1.25 + 关键按钮加大（主按钮 110rpx）+ 行高随字号重算（1.4 倍），不简单 scale 整页（会糊）｜为什么问：只 scale 会模糊且布局错位，必须重排字号｜兜底：×1.25 字号重排。

**Q32 语音播报范围** ｜推荐：AI 助手页自动朗读回答（进入页面即开）；通知详情提供「朗读」按钮；按钮/图标不加全站语音（成本高）｜为什么问：语音是适老核心功能，范围定死避免蔓延｜兜底：仅 AI 助手页自动朗读。

**Q33 对比度要求** ｜推荐：正文 ≥4.5:1、大字(≥18px) ≥3:1；关怀模式下禁用 #9B9B9B 作正文（升到 #6B6B6B 起）｜为什么问：老人视力差，对比度是硬指标｜兜底：Token 校验表逐色算过。

**Q34 点击热区** ｜推荐：所有可点元素热区 ≥88rpx（44px），视觉小的元素（返回箭头/关闭 X）用透明 padding 补足；相邻热区间距 ≥16rpx｜为什么问：44px 是 iOS HIG 最小热区，老人手指更大｜兜底：按 88rpx 执行。

**Q35 色弱/色盲处理** ｜推荐：状态不只靠颜色——status-tag 加文字+图标双编码；报修状态时间轴用图标区分｜为什么问：约 8% 男性色弱，纯色编码会被评审挑刺｜兜底：文字+图标双编码。

**Q36 关怀模式布局重排** ｜推荐：快捷宫格 2×4 → 1×2 大格（每格 200rpx 高）；列表行高 96→128rpx；banner 文字加大｜为什么问：只放大不重排=文字溢出/挤压，必须逐块重排｜兜底：宫格重排为 2 列大格。

**Q37 语音按钮位置** ｜推荐：全局搜索框右侧、报修描述框内、AI 助手底栏左侧，三处统一 88×88rpx 圆形主色底白话筒图标｜为什么问：语音按钮位置一致才形成肌肉记忆｜兜底：三处统一。

**Q38 行距与段距** ｜推荐：正文行高 1.4（32rpx 字 → 44rpx 行高）；关怀模式行高 1.5；段落间距 16rpx；列表行内上下留白 ≥24rpx｜为什么问：行距直接影响可读性与适老体验｜兜底：按推荐。

### E 组 · 内容与素材（Q39–Q45）

**Q39 图片素材来源** ｜推荐：先出占位图（PIL 生成/unsplash 风格图占位），后续用户可换真实社区照片｜为什么问：素材来源决定版权合规与工期｜兜底：占位图。

**Q40 岭南 IP 插画** ｜推荐：文字+图标弱化处理；自绘少量线条 SVG（镬耳墙/骑楼轮廓）用于空状态与启动页；不依赖外部插画师｜为什么问：插画外部定制工期不可控，需确认自绘可行｜兜底：纯线条自绘。

**Q41 启动页** ｜推荐：主色渐变底 + 小程序名「社区便民」+ 一句 slogan + 镬耳墙线条装饰，静态图 750×1334｜为什么问：启动页是作品第一印象（创新设计分）｜兜底：按推荐静态图。

**Q42 分享卡片** ｜推荐：1000×800px，主色底+标题+小程序码占位框；分享路径=首页｜为什么问：分享是增长（10%）得分点，卡片需提前设计｜兜底：按推荐。

**Q43 占位图规格清单** ｜推荐：banner 750×300、空状态插画 480×480、头像 120×120、分享卡片 1000×800、启动页 750×1334｜为什么问：规格一次给全，前端不用逐张问｜兜底：按推荐。

**Q44 隐私政策/协议页样式** ｜推荐：静态文本页，正文 28rpx、标题 32rpx、行高 1.5；首次登录弹窗=底部弹层半屏，按钮「同意并继续」主按钮/「不同意」次按钮｜为什么问：合规是硬性要求（材料完整性+评审合规）｜兜底：按推荐。

**Q45 空状态插画风格** ｜推荐：线条风（与岭南元素一致），主色单色+辅助色点缀，不用写实照片｜为什么问：插画风格不统一会造成 8 页拼凑感｜兜底：纯色块+图标。

## 6. 工作流程（8 阶段）

| 阶段 | 输入 | 动作 | 输出 | 验收 |
| --- | --- | --- | --- | --- |
| 1 接收与自检 | lead 激活指令 + PRD 等输入文件 | 读 PRD/答案汇总/环境速查；核对 8 页面 4 组件与 PRD P0 对齐 | 输入自检记录（缺失项报 lead） | PRD 已读、无缺失或缺失已上报 |
| 2 发问卷 | 本规范第 5 节 | 45 问+推荐默认值发给 lead，注明「可回全按推荐」 | 问卷消息（存档进答案汇总） | 问卷已发出 |
| 3 收答案摘要 | lead 转达用户答案 | 摘要确认：与推荐值的差异逐条列出 | 向 lead 的摘要确认消息 | 用户逐项确认或默认通过 |
| 4 出 Token（先行） | 答案（或默认值） | 写 `docs/03-design-tokens.md`：色板/字号/间距/圆角/阴影/层级/CSS 变量示例 | Token 最小可用版 | 前端可零疑问引用 |
| 5 出设计预览表 | Token + PRD | 写 `docs/03-设计预览表.md`：8 页线框+元素清单+状态+组件规范+切图规范 | 完整预览表 | 每页五态齐全 |
| 6 出 HTML 预览（可选） | 预览表 | 生成 `docs/03-preview/index.html`（至少首页/AI助手/报修创建 3 页可切换） | 静态预览 | 浏览器双击可看、无横向滚动 |
| 7 用户确认迭代 | 预览表/预览页 | 请用户逐页确认/提修改意见，≤3 轮；超轮请项目经理仲裁 | 修改记录+终稿 | 用户说「同意」= G3 通过 |
| 8 交接归档 | 终稿 | 通知架构师（设计规范+交互说明）；前端由架构师随任务卡转交；汇总报告给 lead | 交接消息+文件路径 | 下游确认收到 |

**硬性规则**：
- 先问卷后动手；用户说「同意」前不进入下一阶段（Token 先行是并行例外，仍须在预览表确认后定稿）。
- 每页必须写清交互状态，杜绝前端自由发挥。
- 严格对齐 PRD P0，不自行新增功能。
- Token 先行实战经验：Design Token 当天先落盘最小可用版（色板/字号/间距/圆角）供前端起步，预览表再走用户逐页确认——不要让前端空等。

### 7.3 组件规范（尺寸与状态）

**① 按钮（button）**
| 档位 | 高度 | 字号 | 圆角 | 用途 |
| --- | --- | --- | --- | --- |
| 大 | 96rpx | 34rpx 加粗 | 16rpx | 主 CTA：提交报修/一键拨号/同意并继续 |
| 中 | 80rpx | 32rpx | 16rpx | 卡片内操作：查看详情/重新加载 |
| 小 | 64rpx | 28rpx | 16rpx | 筛选/标签按钮 |
| 关怀模式主按钮 | 110rpx | 36rpx 加粗 | 20rpx | 同上主 CTA |
- 类型：主按钮（砖红底白字）、次按钮（白底砖红字+2rpx 描边）、幽灵按钮（透明底砖红字）、文字按钮（主色 28rpx 无底）。
- 状态：默认（#C0522F）→ 按压（#A64627 + scale(0.98)，100ms）→ 禁用（40% 透明度，不响应点击）。
- 热区：视觉尺寸不足 88rpx 时用透明 padding 补足；按钮间距 ≥24rpx 防误触。

**② 输入框（input）**
- 尺寸：高 96rpx，内边距 0 24rpx，圆角 16rpx，边框 2rpx --line。
- 状态：默认（#EEEAE3 边框）→ 聚焦（#C0522F 边框 + 0 0 0 8rpx rgba(192,82,47,0.15) 外发光）→ 错误（#C0392B 边框 + 24rpx 错误提示在下方）→ 禁用（底色 #F5F3EF，文字 #9B9B9B）。
- 文字 32rpx --text-1；placeholder 28rpx #9B9B9B；字数统计右下 24rpx。
- 多行文本域：最小高 160rpx，右上角语音按钮 88rpx。

**③ 卡片（card）**
- 白底、圆角 24rpx、阴影 --shadow-card、内边距 32rpx、卡片间距 24rpx、页边距 32rpx。
- 可点卡片：整卡 :active 变 #FBF8F4 底色，右侧「>」箭头 28rpx #9B9B9B。
- 卡片内分区：标题区（34rpx 加粗）/ 内容区（28-32rpx）/ 操作区（底部按钮，右对齐）。

**④ 标签（status-tag）**
- 胶囊：高 48rpx，内边距 0 20rpx，圆角 24rpx，字 24rpx 加粗，浅底深字+1rpx 同系边框（色值见 7.1 工单状态色表）。
- 图标：状态前加 24rpx 圆点图标，双编码（文字+图标+颜色），色弱可辨。

**⑤ 空状态（empty-state）**
- 结构：插画/图标区 240rpx 高 → 主文案 30rpx #6B6B6B → 次文案 26rpx #9B9B9B（间距 16rpx）→ 引导按钮（中档，距文案 32rpx）。
- 变体：空数据（「还没有报修记录，去报修」+按钮）、加载失败（「😥 加载失败」+重新加载）、断网（「网络开小差了」+重新加载+提示检查网络）、未登录（「登录后查看我的报修」+去登录按钮）。

**⑥ 对话气泡（ai-bubble）**
- AI（左）：白底、30rpx 字、44rpx 行高、圆角 24rpx 左上角 8rpx、内边距 24rpx 32rpx、最大宽 75%。
- 用户（右）：砖红渐变底（135deg #C0522F→#D96B3F）、白字、圆角右上 8rpx。
- 头像：64rpx 圆形，与气泡间距 16rpx。
- 附件：引用条（顶部 2rpx #3E6E5F 分隔 + 24rpx #3E6E5F 来源文字）、反馈（👍/👎 28rpx，点后变实心主色）、免责（24rpx #9B9B9B，每条 AI 回答尾部）。
- 状态：加载=「正在思考…」三点动效（8s 超时转兜底话术+拨号按钮）；发送失败=气泡右下角红色「!」+点击重发。

## 8. 质量标准与验收清单（≥15 条）

1. **对比度**：正文 ≥4.5:1、大字 ≥3:1；#C0522F 白字 4.68:1、#6B6B6B 米白底 4.9:1，均已验算。
2. **点击热区**：所有可点元素 ≥88rpx（44px），相邻热区间距 ≥16rpx。
3. **适老正文**：常规 ≥15px、关怀模式 ≥20px；按钮文字常规 ≥17px、关怀 ≥21px。
4. **关怀模式**：字号重排（非整页 scale）、宫格重排大格、对比度升级，3 项齐全。
5. **每页五态**：8 页面全部含默认/空/加载/错误/断网状态说明。
6. **状态双编码**：报修 5 态用文字+图标+颜色，不单靠颜色。
7. **图标统一**：线性 2px 描边、圆角端点；TabBar 双态各一张。
8. **单位统一**：全文档 rpx，无 px 混用（切图尺寸除外）。
9. **Token 完整**：色板 ≥20 色值全带 HEX；字号/间距/圆角/阴影/层级五类齐全。
10. **空状态有引导**：每个空状态带一个可执行动作按钮，不死胡同。
11. **语音按钮一致**：搜索/描述/AI 底栏三处语音按钮 88×88rpx、位置固定、图标统一。
12. **AI 可信设计**：引用来源条+有用/无用反馈+免责声明，三件套每条回答必备。
13. **岭南元素落点**：空状态插画、启动页线条、首页 banner 至少 1 处可验证。
14. **命名规范**：切图命名示例 ≥10 个，目录结构写明。
15. **禁用态与错误态**：按钮禁用、输入错误、AI 超时兜底均有具体样式。
16. **隐私合规入口**：隐私政策/用户协议页样式+首次登录弹窗已设计。
17. **HTML 预览可用**：浏览器双击打开、无横向滚动、关怀模式可切换演示（如做预览）。

### 9.2 Token 引用方式（前端落地步骤）
1. 前端把 7.1⑦ 的 CSS 变量块粘贴进 `app.wxss`（基础库 ≥2.9 支持 CSS 变量）。
2. 组件样式一律 `var(--brand)`、`var(--font-body)`，**禁止硬编码色值/字号**。
3. 关怀模式：根节点切换 class `care-mode`，变量自动放大，无需逐组件改样式。
4. 变更流程：任何 Token 改动 → UI 设计师在 `docs/03-design-tokens.md` 顶部 CHANGELOG 记一条（日期/变量/旧值/新值/原因）→ 通知架构师与前端 → 前端按新值回归。改样式 = 契约变更，不走私聊。

### 9.3 视觉走查方法
1. **取样**：微信开发者工具 3 机型截图——iPhone SE(375×667)、iPhone 15 Pro(393×852)、Android 1080×2400。
2. **比对**：截图与 HTML 预览稿并排，逐项核对：色差（取色 ΔRGB≤8）、间距误差 ≤4rpx、字号误差 ±2rpx、圆角 ±2rpx。
3. **走查清单（12 项）**：状态标签色值 / 点击热区 / 关怀模式字号 / 空状态样式 / 断网提示 / 键盘遮挡输入框 / AI 气泡长文本换行 / 长标题截断 / 图片加载失败占位 / TabBar 双态图标 / 吸顶效果 / Toast 样式。
4. **分级**：P0 阻塞（与 Token 不符、热区过小、关怀模式失效）→ 前端修复后复走；P1 建议（间距微差、文案）→ 记录留档。
5. **记录**：`docs/03-视觉走查记录.md`，表格：机型/页面/问题/截图名/级别/状态。

## 12. 常见坑与经验教训（≥10 条）

1. **字体授权雷区**：嵌入思源之外的商用字体未授权会连累材料合规；一律系统默认字体。
2. **组件库冲突/包体积**：Vant Weapp 与适老化定制冲突多、体积大；自绘轻量组件（本项目 4 组件）可控且省 50% 适配时间。
3. **Token 未先行返工**：前端先写死色值后改主题 = 全局返工；Token 必须比第一个页面先落盘。
4. **rpx/px 混用**：稿子里混写 px 会让前端在 2 倍图换算上出错；文档全部 rpx，切图尺寸单独标注 px。
5. **适老化只放大不重排**：整页 scale 会糊且溢出；必须字号重排+宫格改大格+行高重算。
6. **点击热区 <44px**：返回箭头/关闭 X 视觉小导致老人点不中；用透明 padding 补足 88rpx。
7. **状态色与品牌色混淆**：待受理橙色 #D98E32 与主色 #C0522F 太接近会误读；状态色用浅底深字胶囊独立成系。
8. **空状态遗漏**：8 页只画满数据态，前端遇到空数据自由发挥；每页五态是交付硬指标。
9. **真机与模拟器差异**：字号渲染、安全区（刘海屏）、键盘遮挡只在真机暴露；走查必须含 Android 1080p 机型。
10. **深色模式半成品**：时间不足做半套深色反而扣分；明确「本期不做」，Token 注释留二期。
11. **切图尺寸缺失**：只给图标不给尺寸，前端猜着做；命名带尺寸（icon-home-81.png）一劳永逸。
12. **对比度凭感觉**：#9B9B9B 在米白底只有 2.6:1，作正文不合规；任何浅灰当正文前先算对比度。
13. **AI 回答缺免责**：评审对「AI 幻觉」敏感；每条 AI 回答固定「AI 生成，仅供参考」+来源引用。
