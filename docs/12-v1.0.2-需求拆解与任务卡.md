## §2 现状核查（代码事实，不是推测）

### R1 · 首页空白

**核查结论：确认为真实缺陷，且根因明确。**

| 事实 | 证据 |
|---|---|
| 宫格卡片宽度写死 `331rpx` | `pages/index/index.wxss:305` `width: calc((750rpx - 64rpx - 24rpx) / 2)` |
| 内容区左右 padding 各 `32rpx` | `.content { padding: 0 var(--space-4) … }`，`--space-4: 32rpx` |
| 两列所需宽度 = `331×2 + 24(gap) = 686rpx`，可用宽度 = `750 − 64 = 686rpx` | **余量为 0** |
| 卡片高度写死 `320rpx`，内容仅「图标+标题+两行副标题」 | `index.wxss:306` |

**推论**：只要出现 1rpx 级舍入误差、边框/滚动条占位、或真机 `rpx` 换算出小数，第二张卡片就会被挤到下一行 → 变成 **1 列 4 行**，右侧整片空白、卡内近 40% 竖向空白。截图 1 正是这个形态。

**用户说的"自动补全"= 两层含义，本版两层都做**：
- **A. 横向自适应**：栅格按容器宽度自动等分（永远 2 列，不分设备宽度）。
- **B. 纵向补全**：首屏往下到底部 tabBar 之间不再留白，补 1~2 个内容模块。

### R2 · 服务订单 → 办事大厅

**核查结论：改文案是 3 处 5 分钟；但"名实不符"是产品问题，不是技术问题。**

| 需改位置 | 现值 |
|---|---|
| `app.json` → `tabBar.list[1].text` | 服务订单 |
| `pages/repair/list/index.json` → `navigationBarTitleText` | 服务订单 |

**关键判断**：改名后用户点进去看到的仍是「报修工单列表 + 我要报修」→ 叫"办事大厅"却只办报修，是**名实不符**，评审会被问住。**推荐**：改名同时把该页升格为「聚合入口页」（上方 4 类服务入口 + AI 助手入口 + 下方"我的报修记录"），报修列表降为该页的一个分区或二级页。这需要用户裁决（见 §7 Q1）。

### R3 · AI 文生图

**核查结论：技术上可行，但"直连生图 API"在小程序里不成立，且带合规成本。**

| 约束 | 说明 |
|---|---|
| 不能前端直连 | 小程序要求域名白名单 + 密钥不能进前端；必须云函数代理 |
| 延迟 | 单张 3~10s，用户搜索后"立刻出图"体感不成立 |
| 成本 | 按张计费；演示/比赛期间反复试错会持续烧钱 |
| 内容安全 | 微信要求 AI 生成内容过 `security.imgSecCheck` + **显著 AI 标识** |
| 合规 | 面向公众提供生成式 AI 服务涉及算法备案，与当前"备案整改中"叠加会**加重审核风险** |
| 主包体积 | 主包上限 2MB；本地图库 24 张 × 60KB ≈ 1.4MB，会挤爆 |

**三条路线对比**：

| 路线 | 出图速度 | 断网 | 成本 | 合规风险 | 评审观感 |
|---|---|---|---|---|---|
| **L1 本地图片库 + 意图匹配** | <100ms | ✅ 可用 | 0 | 无（非生成内容） | 稳，但被问"这还是文生图吗" |
| **L2 云端真生成** | 3~10s | ❌ | 按张 | 高 | 炫，但可能卡在合规/超时 |
| **L3 混合：本地优先 + 云端兜底** | 本地秒出 | 本地部分可用 | 低 | 中 | **推荐**：名称叫"AI 识图配图"，实做本地优先，云端作为可选增强（默认关闭开关） |

**推荐落地口径**：对外表述改为「**AI 智能配图 / 图片联想**」——用户搜"药品"，跳药品图；不是每次都重新生成。这样：合规零风险、断网可用、演示不翻车。云端真生成作为 `FEATURE_AI_IMAGE_GEN=false` 的**开关**预留，赛后再开。

### R4 · 离线 AI 回答

**核查结论："离线大模型"在小程序里做不到，必须改名改预期；"离线知识库问答"可做，且是加分项。**

| 方案 | 可行性 |
|---|---|
| 端侧跑小参数 LLM | ❌ 主包 2MB / 总包 20MB，无 WebGPU/WASM 推理环境 |
| 端侧检索式问答（关键词+同义词+同义扩展打分） | ✅ **唯一可行**，命中即答，<50ms |
| 云端答案本地缓存（最近 N 条） | ✅ 可做，覆盖"高频问题二次询问" |
| 断网时先请求再兜底 | ❌ 云调用默认 5s 超时，用户会干等 → **必须本地优先**，不做网络探测式主路径 |

**必须向用户/评委讲清的能力边界**：离线只能回答**知识库覆盖到的问题**（本版目标 40 条），未命中时给电话与线下地址兜底，**不假装能答**。这是"可用性保障"，不是"离线大模型"。
