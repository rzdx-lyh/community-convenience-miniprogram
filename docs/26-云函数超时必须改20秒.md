# 26 · 云函数超时必须改成 20 秒（「网络异常」最后一步）

> 这篇只讲一件事：**把 8 个云函数的超时时间从 3 秒改成 20 秒**。
> 不会改，小程序就会「隔一会儿点一次报网络异常，马上再点一次又好了」。

---

## 一、先搞清楚：为什么点一下会报「网络异常」

小程序的每个云函数，在云端都有一个**超时时间**，默认 **3 秒**。

而云函数第一次被呼叫时要做「冷启动」——把 `wx-server-sdk` 这个运行环境从零拉起来。
这一步**普遍要 2~4 秒**，本来就贴着 3 秒的边上，稍微慢一点就超了。

超时的表现是：

| 你点的时机 | 结果 |
|---|---|
| 隔了几分钟第一次点 | ❌ 3 秒没跑完 → 前端弹「网络异常，请检查网络后重试」 |
| 马上再点一次 | ✅ 容器已经热了，1 秒内返回 → 正常显示 |

**所以这不是你的网络问题，也不是代码错了，是云端给的时间不够。**

> 我已经在代码里加了一层兜底：**超时时自动静默重试一次**（容器已热，第二次基本必成）。
> 但这是治标。根治还是要把超时改大，不然每次都要多等一次。

---

## 二、为什么我不能直接替你改

- 微信开发者工具的命令行**不支持**设置超时（`cli cloud functions deploy` 没有这个参数）。
- 代码里的 `config.json` 写了 `timeout: 20`，**但命令行部署不会应用它**。
- 只能在**云开发控制台**网页上手点。

验证现状（命令行查出来的，你可以自己复核）：

```
cli cloud functions info --env cloud1-d5g1xuxxf9eb5b758 --names notice workorder qa

│ (index)   │ status   │ timeout │ runtime       │
│ notice    │ 'Active' │ 3       │ 'Nodejs16.13' │
│ workorder │ 'Active' │ 3       │ 'Nodejs16.13' │
│ qa        │ 'Active' │ 3       │ 'Nodejs16.13' │
```

`timeout` 那一列是 **3**，就是它。

## 三、改法（两种方法，选一个）

### 方法 A：在微信开发者工具里改（推荐，不用登腾讯云）

1. 打开**微信开发者工具**，导入本项目根目录。
2. 点顶部工具栏的 **「云开发」** 按钮（长得像一朵云，在「编译」右边）。
   → 会弹出「云开发控制台」窗口。
3. 左侧菜单点 **「云函数」**。
4. 你会看到 8 个函数：`auth`、`circle`、`notice`、`phonebook`、`qa`、`service`、`user`、`workorder`。
5. **点第一个函数名**（比如 `auth`），进入它的详情页。
6. 找到 **「配置」** / **「函数配置」** 这一块（通常在页面上方 Tab 或右侧）。
7. 里面有一项 **「超时时间」**（单位：秒），现在显示 `3`。
   → 把它改成 **`20`**。
8. 点 **「保存」** / **「确定」**。
9. **回到第 5 步，把剩下 7 个都改一遍。**（8 个函数每个都要改，只改一个没用）

### 方法 B：在腾讯云开发控制台网页改

1. 浏览器打开 <https://tcb.cloud.tencent.com/>，用**同一个微信**扫码登录。
2. 选中环境 **`cloud1-d5g1xuxxf9eb5b758`**。
3. 左侧 **「云函数」** → 点函数名 → **「函数配置」** → **「编辑」**。
4. **超时时间** 改 `20` → 保存。
5. 同样 **8 个都要改**。

## 六、如果改完还是报「网络异常」

现在代码已经会把**真实原因**打印到开发者工具的「Console（控制台）」面板了。
打开 **调试器 → Console**，找 `[cloud] xxx 调用失败：` 开头的那行，对照下表：

| Console 里的原文（关键片段） | 真正的毛病 | 怎么办 |
|---|---|---|
| `Cannot find module './shared/xxx'` | 云函数打包漏了 `shared/` | 跑 `npm run build:cf -- --clean` 再重新部署 |
| `FunctionName parameter could not be found` | 这个函数**根本没部署**上去 | `cli cloud functions deploy` 部署它 |
| `timed out` / `ESOCKETTIMEDOUT` / `超时` | 还是超时（本篇没改成功，或冷启动特别慢） | 确认本篇第 4 步复查过了；再不行把超时提到 60 |
| `cloud api isn't enabled` / `-501000` | 云环境没初始化，或 env ID 配错 | 检查 `miniprogram/config/env.ts` 的 `CLOUD_ENV_ID` |
| `Permission denied` / `401` | 登录态失效 | 代码会自动重登一次；反复出现再看 `users` 集合有没有数据 |

**把那行原文截图发我**，比我猜快得多。
