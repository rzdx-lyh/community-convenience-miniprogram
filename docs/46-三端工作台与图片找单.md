# 三端工作台与图片找单（v1.2.8）

> 目标：让居民端已有的 4 类 / 38 项服务在物业、管理和维修端都有可见、可操作的业务入口，同时补齐工单图片检索与维修闭环。

## 1. 三端职责

| 端口 | 核心能力 |
|---|---|
| 居民端 | AI 管家、服务预约、报修、地图、通知、电话簿 |
| 管理端 / 物业端 | 服务全景、工单态势、关键词筛选、图片找单、受理派单 |
| 维修端 | 抢单池、我的工单、开始处理、确认完工、图片与位置查看 |

物业、社区管理员、超级管理员共用管理端，但工作台标题分别显示“物业运营台”“社区治理台”“平台总控台”。

## 2. 居民服务映射

管理端直接读取 `miniprogram/config/service-grid.ts` 的本地单一真源：

- 生活基础服务
- 健康养老服务
- 便民配套服务
- 文化便民服务

每类卡片展示服务数量、板块数量与代表服务；点击可打开完整板块和 38 项服务清单，避免管理端与居民端服务口径漂移。

## 3. 图片找报修

1. 管理端点击“拍照找单”。
2. 微信选择相册或相机图片。
3. 图片上传至云存储 `workorder-search/` 目录。
4. 调用 `workorder:analyzeImage`，请求携带工作人员 `token`。
5. 识别结果优先按报修分类匹配同类别工单，再回退到标题/描述关键词匹配。
6. 未配置视觉模型时保留文本搜索与状态筛选，不阻断工作台。

## 4. 工单闭环

```text
居民提交 pending
  → 管理端受理 assign
  → 维修端接单/开始处理 process
  → 维修端确认完工 done
  → 居民端查看最新进度
```

关键规则：

- 管理端受理后工单进入“待派单池”，不占用维修人员名额。
- 维修端抢单后才把 `assignee` 绑定到具体维修人员。
- 管理端只负责受理派单；处理动作由维修端完成。
- 所有工作人员写操作都同时校验 staff token、会话端与账号状态。

## 5. 接口

| 动作 | 调用方 | 说明 |
|---|---|---|
| `workorder:managementList` | 管理端 | 全量工单 |
| `workorder:staffList` | 管理 / 维修端 | 按端口隔离工单池 |
| `workorder:handle` | 管理 / 维修端 | 带 staff token 的状态流转 |
| `workorder:analyzeImage` | 居民 / 管理端 | 图片识别；管理端需 staff token |

## 6. 演示路径

1. 居民端提交一条带图片的报修。
2. 使用 `property01` 登录管理端，查看工单态势与服务全景。
3. 点击“拍照找单”验证图片识别和同类工单筛选。
4. 管理端点击“受理派单”。
5. 使用 `repair01` 登录维修端，从抢单大厅接单。
6. 依次点击“开始处理”“确认完工”。
7. 回到居民端查看工单状态已同步。
