## 1. 诊断：现在为什么"不像 Agent"

对着 v1.0.2 逐条看，问题不在功能数量，而在**交互范式**：

| 现象 | 本质 | 用户感受 |
|---|---|---|
| AI 助手只有"问一句、答一段" | 只有 RAG 问答，没有**动作** | 是个搜索框，不是助手 |
| 办事要走"点宫格 → 选子项 → 填表 → 提交" | 用户承担全部流程编排 | 和普通政务 App 没区别 |
| 首页 8 个入口平铺 | 没有**上下文感知**，不主动 | 冷启动、每次从零找 |
| 报修要用户自己判断"这是水电还是公共设施" | 分类判断被推给用户 | 填错类、被退回 |
| 状态要用户自己点进去看 | 没有**主动播报** | 不知道进展，反复问 |

**结论**：缺的不是页面，是「**一句话 → Agent 拆解 → 补参 → 确认 → 执行 → 回执 → 主动跟踪**」这条闭环。这条闭环做出来，8 个功能也会像 30 个。

## 2. 参考拆解：政务超级 App 的可迁移模式

以粤省事为代表的省级政务 App，值得抄的是**信息架构与信任设计**，不是它的省级业务。逐条判断"社区级能不能用"：

| # | 参考模式 | 粤省事里的形态 | 社区级迁移 | 判断 |
|---|---|---|---|---|
| M1 | 分类办事大厅 | 社保/医保/公积金/户政/出入境… | 社区 8 类：社保医保、居住证、养老助餐、生活缴费、证明开具、预约取号、政策查询、报修上门 | ✅ 直接迁移（分类收敛到 8 个） |
| M2 | **一件事一次办** | 新生儿一件事、退休一件事 | 新生儿一件事、退休养老一件事、租房备案一件事（每件打包 3~5 个事项） | ✅ 强推荐，最像"办事" |
| M3 | **电子证照包** | 我的证照、亮证 | 居住证明、疫苗档案、家庭健康档案 | ⚠️ 设计可做，**真实亮证需授权**，演示须标注 |
| M4 | **预约取号** | 大厅预约、排队进度 | 社区事务大厅 3 个业务、时段预约、当前排队 | ✅ 可做（无支付、无实名） |
| M5 | **办事进度** | 我的办事、进度查询 | 报修/预约/申请三类统一时间轴 | ✅ 直接迁移 |
| M6 | 政策解读 / 智能客服 | 政策库、智能问答 | AI 政策计算器：条件问答 → 能不能领 → 材料清单 | ✅ 差异化亮点 |
| M7 | 长者专区 / 关怀版 | 大字、语音、常用四件事 | 已有 `care-mode`，补"长者四件事"入口 | ✅ 低成本高感知 |
| M8 | 材料预检 | 材料清单、容缺受理 | 拍照/勾选 → 齐全度预检 | ⚠️ OCR 需后端；纯勾选版可做 |

**明确不抄**：跨省通办、出入境、税务、公积金、支付缴费。理由：社区级无权限、无资质，且 PRD §3 已把"支付/缴费"列为 P2 不做。缴费在原型里只做**入口占位**，不做支付。

## 3. 新信息架构（IA）

**从 4 Tab 改 5 Tab，把 Agent 放到中心位**（tabBar 允许 2~5 项，5 项是上限，够用）：

```
首页        办事        AI 管家        圈子        我的
├ 一句话输入  ├ 搜索      ├ 对话         ├ 帖子      ├ 证照包
├ 主动提醒    ├ 一件事    ├ 步骤卡       └ 路况      ├ 我的办事
├ 常用 8 服务 ├ 8 分类    ├ 确认卡                  ├ 预约记录
├ 社区动态    ├ 报修记录  └ 回执卡                  └ 关怀模式
└ 紧急求助
```

**为什么 Agent 不放右上角浮球**：浮球命中率低、遮挡内容、适老化差；中心 Tab 是"一等公民"信号，且符合 44px 触控与拇指热区。

**保留不动的**：紧急求助（红色，一级入口）、社区动态、报修记录、关怀模式。它们是既有资产，不重做。

## 5. Agent 交互模型（本设计的核心）

### 5.1 五步闭环

```
① 理解   用户说"我家厨房水管漏水了"
          → 识别意图：报修工单（置信度 92%），非问答
② 抽取   类别=水电 · 位置=厨房 · 时间=今天下午（从原句抽取，不让用户重填）
③ 补参   缺"楼栋单元" → 一次只问一个，给候选 chip（1/2/3/7 号楼），可跳过
④ 确认   生成"工单草稿卡"：字段可点改，底部【确认提交】【再改改】
          → 提交前明确写"将提交给物业服务中心"
⑤ 回执   工单号 W20261018-0037 · 30 分钟内响应 → 【看进度】【再报一单】
```

### 5.2 状态机（前端可直接落地）

```
idle → understanding(0.6s) → extracting(0.6s)
     → need_param ──用户选择──→ confirm
     → confirm ──确认──→ submitting(0.8s) → submitted
     └─ 任意步 ──用户取消──→ idle（草稿保留，可恢复）
```

### 5.3 三条硬规则

1. **不静默执行**：任何写操作（提交工单/预约）必须先出确认卡，绝不在用户没点"确认"时提交。
2. **一次只问一个**：缺 3 个参数不许一次弹 3 个框；用 chip 点选，减少键盘。
3. **可撤销**：确认卡上每个字段可点改；提交后 5 分钟内可取消（复用既有 pending 取消能力）。

### 5.4 降级（断网/超时）

- 断网：Agent 顶部切"离线知识库"态，只答不办，写操作按钮置灰并提示"联网后可提交"。
- 识别失败：不硬猜，回落成普通问答 + 三个候选意图 chip。
- 大模型超时 8s：直接走规则引擎（关键词），并标注"已使用规则应答"。

## 8. Token 扩展（AI 色系）

现有品牌绿不变（办事=绿），**新增紫蓝系专供 Agent**，让"AI 区域"一眼可辨：

```css
--ai: #5B54D6;              /* AI 主色，白字对比 6.1:1 ✅ */
--ai-deep: #4941B8;         /* 按压 */
--ai-light: #EEECFD;        /* 浅底，深字对比 6.5:1 ✅ */
--ai-grad: linear-gradient(135deg, #7B6CF6 0%, #4F7BF0 100%);
--ai-line: rgba(91, 84, 214, .16);
```

**使用规则**：Agent 相关（输入框、步骤卡、工具标、AI 气泡边）用紫蓝；办事与品牌（按钮、首页头部、宫格）保持绿。**不混用**：一个卡片里不允许两种主色同时当强调色。

**字号**：沿用 §2 阶梯，不新增级别；步骤卡正文用 `--font-sub`（28），确认卡字段值用 `--font-body`（32）。

## 9. 可用性与无障碍

| 项 | 要求 | 本设计落点 |
|---|---|---|
| 触控区 | ≥ 88rpx（44px） | 所有 chip 高 72 + 上下 padding 8；宫格 160 |
| 对比度 | 正文 ≥ 4.5:1 | 紫 `#5B54D6` 配白 6.1:1；灰字仅用于辅助信息 |
| 关怀模式 | 字号 +20~25%，宫格 1 列 | 步骤卡改上下堆叠，确认卡按钮改全宽 |
| 动效 | ≤ 300ms，尊重减弱动效 | 步骤出现用淡入，不做位移大动画 |
| 错误预防 | 写操作二次确认 | 确认卡 + 提交中禁用 + 成功回执 |
| 键盘 | 能点就不打字 | 补参全部 chip 点选，输入框仅兜底 |
