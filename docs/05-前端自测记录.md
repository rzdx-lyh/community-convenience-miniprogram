## 6. 通知卡裁切专项（v1.2 已知坑，本轮重点验证）

**红线**：头部与内容必须在同一滚动容器内做负边距叠压；若头部固定、内容单独 `overflow:auto` 滚动，负边距会把通知卡顶部裁切。

**本轮做法**：
1. 页面根节点 `<view class="page">` 为整页自然流，**没有** `scroll-view`、没有 `overflow:auto` 的独立内容容器，也没有 `position: fixed` 的头部；
2. 通知卡 `margin-top: -72rpx` + `position: relative` + `z-index: var(--z-sticky)`，头部 `z-index` 更低、**未设置** `overflow:hidden`；
3. 头部 `padding-bottom: 96rpx`（> 72rpx 叠压量），保证紧急援助行不被卡片压住。

**静态判读**：负边距元素在同一 BFC 内向上偏移，父容器 `.content` 无 `overflow:hidden`，不会被裁切 → 通知标题应完整可见。
**待 DevTools 复核**：打开模拟器后请重点看「停水通知」四字是否完整（这是 v1.1 踩过的坑的具体表现）。
