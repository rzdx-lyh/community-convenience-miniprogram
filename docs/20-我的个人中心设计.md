## 3. 自定义用户名：怎么做到"真的能改"

这一节是这次需求的核心，也是最容易做假的地方（改完只有本页变，一切换页面就露馅）。

### 3.1 问题：作者标识不能直接改名

圈子数据里我自己发的帖子作者是 `who:'3 栋阿明'`，而「我发的」筛选用的是：

```js
POSTS.filter(p => p.who === '3 栋阿明')
```

如果直接把昵称写进 `who`，改名后**筛选立刻失效**——旧帖子的 `who` 还是老名字，「我发的」会变成 0 条。

### 3.2 解法：标识与显示名分离

```js
const ME_SEED = '3 栋阿明';          // 种子数据的作者标识，永不改
function meName(){ return state.prof.name || ME_SEED; }
function dispWho(w){ return w === ME_SEED ? meName() : w; }   // 渲染时替换
function dispAv(w, av){ return w === ME_SEED ? meName().slice(0,1) : av; }
function myPosts(){ return POSTS.filter(p => p.who === ME_SEED); }  // 筛选用标识
```

渲染作者名的地方（2 处 `p-nm`）和头像（2 处 `p-av`）改成 `dispWho` / `dispAv`，筛选逻辑一行没动。

**结果**：改名后圈子里的两条帖子作者名与头像同步变，「我发的」仍然是 2 条。

### 3.3 编辑弹层

点头像或昵称都进同一个弹层：

| 字段 | 约束 | 说明 |
|---|---|---|
| 昵称 | 2–12 字，实时保存草稿 | 少于 2 字拦截并 toast，弹层不关 |
| 头像底色 | 8 色圆点，选中态用外圈同色描边 | 头像**字**取昵称首字，不单独选 |
| 一句话签名 | 最多 24 字 | 显示在昵称下方 |
| 楼栋房号 | 最多 20 字 | 只用于上门服务，标注不对他人公开 |

**为什么头像只让选底色不选图**：一是个人主体小程序拿不到用户头像（`wx.getUserProfile` 已废弃），二是"首字 + 色底"的辨识度反而比一堆模糊自拍高。这是设计取舍，不是省事。

### 3.4 草稿保护

选颜色会重渲染弹层，如果不先收回输入框内容，用户刚打的昵称就没了。

```js
function grabProfD(){                 // 重渲染前把输入框写回草稿
  const n=$('#pName'), g=$('#pSign'), a=$('#pAddr');
  if(n) state.profD.n = n.value.trim();
  if(g) state.profD.s = g.value.trim();
  if(a) state.profD.a = a.value.trim();
}
```

**同一个坑在家庭成员弹层里又踩了一次**（切关系时把已填的称呼清空了），已修：`sheetMember()` 改成只读 `state.memD`，重置逻辑移到 `openMemberAdd()`。

> 这是单文件原型的通用陷阱：**任何会触发 `render()` 的点击，都要先把用户输入收进 state**。

## 4. 新增的四块

### 4.1 家庭与地址

- 成员头像行横向滚动（无滚动条），含「本人 + 成员… + ＋添加」
- 点成员 → 移除确认（说明历史单据仍保留）
- 添加成员：称呼（≤6 字）+ 关系（父亲/母亲/子女/配偶/其他），自动配一个色底
- 地址两条，点「设为默认」即切换，默认地址文案说明"上门服务优先"

### 4.2 我的内容四宫格

| 格 | 计数来源 | 点击去向 |
|---|---|---|
| 我发的 | `myPosts().length` | 我的圈子 · 我发的 |
| 我回复的 | 评论里有 `w==='阿明'` 的帖子数 | 我的圈子 · 我回复的 |
| 我收藏的 | `state.saved` 为真的条数（预置 2） | 我的圈子 · 我收藏的 |
| 我的预约 | 3（单据数） | 我的预约页 |

### 4.3 设置中心

- **3 个通知开关**：工单进度 / 停水停电 / 社区活动，每条带一句"发什么、多久发一次"的说明
- **字号三档**：标准 / 大（`zoom:1.08`）/ 特大（= 关怀模式，宫格两列）
  - 为什么特大直接等于关怀模式：两个都放大字号会让用户不知道该调哪个，合并成一条语义
- **隐私与授权**：列出位置、相册、订阅消息、健康数据四项，每项标当前策略
- **清除缓存**：显示体积，点后 toast（不做真实清理，避免演示时数据丢失）

### 4.4 帮助与注销

- 帮助：3 条常见问题 + 物业客服电话 `020-8888 1234`
- 关于：版本号（引用 `APP_VER` 常量）、开发方、适用范围 + 一句业务边界声明
- **注销**：二次确认弹层，**逐条列出会被清掉的内容**（昵称/预约/发布/收藏/健康档案），并说明"办理中的工单需先完成"

注销这块是合规重点：个人主体小程序必须有注销路径，且要让用户知道自己失去什么。

## 5. 复用了哪些原子件

这页**没有新造轮子**，全部复用 v1.2.0 的原子组件：

| 位置 | 复用组件 |
|---|---|
| 通知开关 | `.asw`（44×26，青绿） |

## 7. 小程序落地要点

| 项 | 做法 |
|---|---|
| 昵称/签名/房号 | `storage` 本地存 + 云数据库 `users` 表同步；限制 2-12 字并做敏感词过滤 |
| 头像 | 个人主体拿不到微信头像 → 沿用"首字 + 色底"；若后续有单位主体，可加 `open-type="chooseAvatar"` |
| 家庭成员 | 独立集合 `family_members`（`_openid` + 称呼 + 关系），提交单据时带 `memberId` |
| 字号 | 小程序用 `page-meta` 的 `root-font-size` 或全局 `rpx` 换算；不要用 `zoom`（不生效） |
| 注销 | 必须有：云函数 `user:destroy` 软删 + 7 天冷静期；注销前校验未完成工单 |
