# 22 · AI 询问入口与办事大厅 AI 集群（v1.4.0）

> 需求原文：`我需要在每个页面功能下面做一个AI询问的入口，然后这些入口全部汇总到那个办事那里有个总的AI集群那里`
> 交付物：`docs/03-preview/demo.html`（v1.4.0）
> 自测：六套断言 **294 条**（48 + 29 + 66 + 56 + 33 + 62）全绿

---

## 0. 需求确认块（Phase 0）

| 要素 | 内容 |
|---|---|
| **目标** | 让用户在任何服务页卡住时，就地能问；所有 AI 能力在办事大厅有一个总入口 |
| **输入** | 当前页面 + 服务名；用户问题（预置或自由输入） |
| **输出** | 一段 ≤200 字的答复 + 引用来源 + 「去办理」跳转 + 「转人工」电话 |
| **成功指标** | 7 个服务页都能唤起面板；预置问句命中本地答案率 100%；断网时仍可用 |
| **约束** | 契约冻结（`qa` 只有 5 个动作）；个人主体不能收集健康数据；不预填、不代办 |
| **风险** | 底栏与既有操作条冲突；模型不可用导致演示翻车；问答库覆盖不足显得"很笨" |

### C3 判定：这不是 Agent

每页入口 = **一个底栏组件 + 一次带上下文的路由 + 一组场景模板**，底层是一次 `qa:ask`。
没有自主决策、没有工具链、没有循环 —— 按 AI 工程师的原则，做成"上下文注入 + 场景模板"，不包装成 Agent。

## 3. 办事大厅 AI 集群

8 张卡，按「我想干什么」排，不按部门排：

| 场景 | 副标题 | 示例问句 |
|---|---|---|
| 办事指南 | 材料、流程、要跑几趟 | 办居住证要带什么？ |
| 报修与进度 | 派单到哪了、多久上门 | 我的报修派单了吗？ |
| 健康咨询 | 指标怎么看、疫苗与义诊 | 血压 145/92 要紧吗？ |
| 配餐与营养 | 今天吃什么、忌口能不能吃 | 控糖的一天怎么吃？ |
| 费用与户号 | 水电气怎么算、怎么绑户号 | 这个月水费为什么涨了？ |
| 找地点 | 雨伞、充电宝、快递点在哪 | 最近的共享雨伞在哪？ |
| 邻里互助 | 发帖、借东西、处理纠纷 | 闲置怎么发比较快出手？ |
| 应急求助 | 停水漏水、急病、独居老人 | 家里漏水先找谁？ |

**两个细节**：
1. **搜索时隐藏集群** —— 用户已经在搜具体服务，再摆 8 张卡是干扰。
2. **集群卡不跳页** —— 直接在当前页升面板，与页面级入口共用同一个组件。

## 4. 本地问答库（45 条）

这是本版最容易被低估的部分。`QA_BANK` 覆盖了 7 页 × 3 条 + 8 场景 × 3 条预置问句，每条都有：

- 一段 60-120 字、带具体数字的答复（如"水费阶梯 20 吨以内 2.6 元/吨"）
- 1-2 个引用来源（`服务指南 · 水费` / `膳食指南（2022）`）

**作用有两个**：模型可用时它是兜底，模型不可用时它就是主答案。演示现场网络不可控，**没有这层就等于把演示押在别人的接口上**。

### 匹配策略（本轮修复的真 bug）

第一版用 `QA_BANK[q]` 全等匹配，结果用户输入"可以改时间吗"（**没打问号**）直接落空，掉进"建议转人工"的通用兜底。

改成两级：

```js
function normQ(q){ return String(q||'').replace(/[\s?？!！。.,，、~]+$/g,'').trim(); }
function bankAnswer(q){
  const k = normQ(q);
  if (QA_BANK[k]) return QA_BANK[k];          // 1. 去尾部标点后精确匹配
  if (QA_BANK[k+'？']) return QA_BANK[k+'？'];
  // 2. 长句包含兜底（要求 ≥4 字，避免短词误命中）
  ...
}
```

用户输入很少带规范标点，全等匹配会大面积落空——这类"看起来能用、实际命中率很低"的实现，只有写断言才会暴露。

## 5. 降级与边界

| 情况 | 表现 |
|---|---|
| 模型正常 | 走 `text.pollinations.ai`，`system` 里带场景上下文 |
| 模型失败 / 断网 / 无 `fetch` | 自动改用 `QA_BANK` → `localAnswer`，金色标注「当前为本地答案」 |
| 用户问库外问题 | `localAnswer` 的通用兜底：建议搜索 / 看地图 / 发圈求助 |
| 任何时候 | 底部常驻「转人工 · 020-8888 1234」 |
| 医疗类问题 | 只给一般性建议 + 明确提示就医，不给诊断 |

**明确不做的**：不预填表单、不代替用户提交、不承诺"已帮你办好"。AI 只答 + 给一个跳转按钮。

## 7. 自测（`.workbuddy/_t16.mjs`，62 条全绿）

| 组 | 断言 | 关键点 |
|---|---|---|
| 1 覆盖范围 | 15 | 7 个服务页都有横条；**首页/办事/圈子/我的等 8 页都没有** |
| 2 与底栏共存 | 5 | 预约页 `.up` 且 `bottom=61px`；缴费页不抬升 |
| 3 上下文文案 | 3 | 预约页显示"保洁"、设备页显示"共享雨伞" |
| 4 面板结构 | 7 | 标题带页面名、3 条预置、输入框、转人工 |
| 5 本地兜底 | 9 | **答案含 135/85**、有引用、标注本地、给去办理 |
| 6 自由输入 | 3 | 回车发送、命中改约库、空输入拦截 |
| 7 去办理 | 2 | 关面板且停在原服务页 |
| 8 集群 | 6 | 8 卡、场景名齐全、**搜索时隐藏** |
| 9 场景问答 | 5 | 办事指南 → 居住证答案 |
| 10 降级 | 4 | 转人工电话；离线仍出本地答案 |
| 11 回归 | 4 | 圈子浮钮不受影响、配餐页横条让位、首页宫格正常 |

第 1 组的反向断言（"其他 8 页没有横条"）是为了防止以后有人图省事给全站加横条——那会让首页和圈子变得很吵。

## 8. 契约影响（必须走流程）

真实落地需要在 `qa:ask` 上加一个字段：

```json
{ "action": "ask", "question": "...", "context": { "page": "record", "svc": "健康档案" } }
```

- `qa` 分组当前是**冻结状态**（v1.1，5 个动作），加字段属于契约变更
- 按规矩要写《契约变更记录》并同步前后端，**本轮只做原型，未改契约**
- 若最终不批准，退路是：上下文拼进 `question` 前缀（不优雅但零契约改动）
