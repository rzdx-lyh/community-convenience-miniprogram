# 25 · 云控制台操作图解教程（照着点就行）

> 适用：第一次用微信云开发控制台。
> 全程在**云开发控制台**里操作，不需要写代码、不需要命令行。
> 预计 15 分钟。做完之后小程序才有真数据可用。

---

## 开始前，先认清这两个页面

控制台左侧有一排菜单，本教程只用到**两个**：

```
概览
运营分析
数据库     ← 第 2~4 步在这里（建集合、建索引、导数据）
存储
云函数     ← 你已经在这里建过云函数了
AI
用量管理
扩展能力
```

⚠️ **最容易犯的错**：在「云函数」里点「创建云函数」，然后输入 `users`。
`users` 不是云函数，是**数据库集合**。集合要在「数据库」里建。

## 第 1 步：打开控制台

两种方式，任选其一：

- **方式 A（推荐）**：微信开发者工具顶部工具栏 → 点「**云开发**」按钮
- **方式 B**：浏览器打开 `https://cloud.weixin.qq.com/` → 用微信扫码登录 → 选你的小程序

进去后左上角应能看到环境名：**cloud1-d5g1xuxxf9eb5b758**。

✅ **这一步算成功**：能看到左侧那排菜单，且顶部显示上面这个环境名。

---

## 第 2 步：建 8 个集合

1. 左侧点「**数据库**」
2. 找到集合列表右上角的「**+**」按钮
3. 弹窗里输入集合名 → 点确定

**要建 8 个，名字一个字都不能差**（全小写、下划线）：

| 顺序 | 集合名（直接复制） |
|:-:|---|
| 1 | `users` |
| 2 | `workorders` |
| 3 | `notices` |
| 4 | `phonebook` |
| 5 | `qa_feedback` |
| 6 | `qa_sessions` |
| 7 | `circle_post` |
| 8 | `service_category` |

✅ **这一步算成功**：左侧集合列表里能看到 8 个名字，每个后面显示「0 条」。

❌ **如果建成了云函数**：去「云函数」列表，找到它，右键删除，然后回「数据库」重来。

---

## 第 3 步：建 1 个唯一索引（**必须在导数据之前**）

这一步只有 1 个，但**顺序不能反**。反了就得删库重来。

1. 左侧点「**数据库**」
2. 在集合列表里点一下 **`users`**
3. 上方切到「**索引管理**」标签
4. 点「**新建索引**」
5. 按下面填：

| 字段 | 填什么 |
|---|---|
| 索引名称 | `uniq_accountId` |
| 索引属性 | **唯一** ← 这个最关键 |
| 字段 | `accountId` |
| 排序 | 升序 |

6. 点确定，等状态变成「**正常**」（可能要几秒）

✅ **这一步算成功**：`users` 的索引列表里出现 `uniq_accountId`，属性是「唯一」，状态「正常」。

> 为什么必须唯一：社区账号（`accountId`）如果重复，两个居民会共用一个档案。
> 靠代码查重挡不住并发，只能靠数据库唯一索引。

---

## 第 4 步：导入数据（6 个文件，一个个导）

我已经把数据拆好了，在项目里这个目录：

```
社区便民小程序/scripts/seed/
├── import/users.json              4 行
├── import/workorders.json         3 行
├── import/notices.json            7 行
├── import/phonebook.json         11 行
├── import/circle_post.json        8 行
└── import/service_category.json   4 行（每条里含 38 个子服务）
```

⚠️ **导入请用 `import/` 子目录里的文件**（后缀 `.json`，内容是每行一个对象）。
外层还有一份 `.jsonl`，内容完全相同，只是有些系统的文件选择框不认 `.jsonl` 后缀。

**每个文件对应一个集合**，导 6 次，`qa_feedback` 和 `qa_sessions` 不用导（它们运行时才产生数据）。

单次操作：

1. 左侧点「**数据库**」
2. 点集合列表里的 **`users`**
3. 点上方「**导入**」按钮
4. 选文件：`scripts/seed/import/users.json`
5. 冲突处理选「**Insert**」（不是 Upsert）
6. 点确定，等提示「导入成功」

然后把上面表格里剩下的 5 个文件，各重复一遍（注意：**点对应的集合，再导入对应的文件**，别导错）。

对应关系：

| 点这个集合 | 导入这个文件 | 导完应有 |
|---|---|:-:|
| `users` | `import/users.json` | 4 条 |
| `workorders` | `import/workorders.json` | 3 条 |
| `notices` | `import/notices.json` | 7 条 |
| `phonebook` | `import/phonebook.json` | 11 条 |
| `circle_post` | `import/circle_post.json` | 8 条 |
| `service_category` | `import/service_category.json` | 4 条 |

✅ **这一步算成功**：6 个集合的条数与上表完全一致，合计 **37 条**。

❌ **如果提示「导入数据格式不正确，请检查是否为 JSON Lines 格式」**：说明导的是 `.json` 数组文件。**必须导 `.jsonl`**（每行一个对象）。这是控制台的硬要求，数组格式它不认。

**导入前 5 秒自检**：用记事本打开文件，第一行应该直接是 `{"_id":...`，
**开头不能是 `[`**，结尾也不能是 `]`。有方括号就是数组格式，导不进去。

❌ **如果 `users` 导入报「唯一索引冲突」**：说明你导了两次。清空 `users` 集合重导一次即可。

## 第 5 步：配置环境变量（可跳过，但建议配 1 个）

1. 左侧点「**云函数**」
2. 找到 **`qa`** 这个函数，点进去
3. 切到「**函数配置**」标签
4. 找到「环境变量」，新增一条：

| 变量名 | 值 |
|---|---|
| `DEEPSEEK_API_KEY` | 你自己的 DeepSeek API Key |

> **不配也能跑**：AI 会自动降级用社区知识库回答，界面上会标注「当前为本地答案」。
> 这是设计内的降级路径，不算故障。演示当天没 Key 也能讲。

✅ **这一步算成功**：`qa` 函数的环境变量里能看到 `DEEPSEEK_API_KEY`。

⛔ **检查一下**：云函数里**不要**有 `CCF_FORCE_MOCK=1` 这个变量。有的话删掉，否则真机拿到的还是假数据。

## 常见错误对照表

| 你看到的现象 | 原因 | 怎么办 |
|---|---|---|
| 集合列表显示 0 个 | 建到「云函数」里了 | 去「数据库」重建 |
| 提示「请检查是否为 JSON Lines 格式」 | 导的是 `.json` 数组文件 | 改导同名 `.jsonl` |
| 文件选择框里没有 `.jsonl` | 选择框按后缀过滤 | 把文件改名成 `.json` 再选（内容不变） |
| 导入提示唯一索引冲突 | 同一份数据导了两次 | 清空该集合，只导一次 |
| 唯一索引建不上（状态「异常」） | 先导了数据，`accountId` 有重复 | 清空 `users`，**先删索引重建**，再导 |
| `service_category` 导完只有 4 条就以为错了 | 正常 | 4 条是对的，每条里嵌套 38 个子服务 |
| 真机打开一片空白 | 云函数没传或数据没导 | 先看第 6 步条数对不对 |
| 真机提示「加载失败」 | `USE_MOCK` 还是 true 或云函数没传 | 先别急着改开关，回来找我 |
| **模拟器一直显示旧版本、Ctrl+B 没反应、改了代码不生效** | 编译失败但 IDE 没弹错误，模拟器只能停留在上一次成功的旧构建 | **用 `cli preview` 跑一次，它会打印真实编译错误**（看模拟器看不出来） |
| 报 `WXML file not found: ./components/xxx/index.wxml` | `usingComponents` 写了**绝对路径** `/components/xxx/index`，本项目编译器解析不了 | 改成**相对路径**，注意层级：`pages/phonebook/` 用 `../../components/…`，`pages/notice/list/` 用 `../../../components/…` |

## 附：为什么数据要拆成 6 个文件

控制台的「导入」是**按集合逐个导**，文件里只能装**这个集合的记录数组**。

原来项目里只有 `scripts/seed-data.json`，长这样：

```json
{ "users": [...], "notices": [...], "phonebook": [...], ... }
```

这是一整个大对象，直接导进任何一个集合都会报格式错误。
而且控制台要的是 **JSON Lines**（每行一个完整 JSON 对象），不是 JSON 数组：

```jsonl
{"_id":"u-1","nickName":"李明",...}
{"_id":"u-2","nickName":"张阿姨",...}
```

所以现在 `node scripts/seed.mjs` 会额外生成 `scripts/seed/` 目录：
- `xxx.jsonl` ← **导入用这个**
- `xxx.json` ← 数组格式，给程序读，不要导
