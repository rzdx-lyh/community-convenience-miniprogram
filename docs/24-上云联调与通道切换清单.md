## 0. 先纠正一个说法

我上一轮说"下一步该把 `USE_MOCK` 置 false"——**这个说法不准确**，按契约附 C 是条件式的：

| 路径 | `USE_MOCK` | 前提 |
|---|:-:|---|
| **已上云** | ⛔ 必须 `false` | 联调冒烟通过 |
| **未上云（当前）** | ✅ 保持 `true` | 界面不得自曝 |

所以**不是"该翻开关了"，而是"先证明已上云，才有资格翻"**。
在没跑通云端之前翻成 `false`，结果就是全站 5 秒超时白屏——比保持 mock 严重得多。

## 2. 四步时序（不可跳步）

```
① 云资源就绪 ──→ ② 联调冒烟 ──→ ③ 置 USE_MOCK=false ──→ ④ 真机冒烟 ──→ 打包
```

## 3. ① 云资源就绪

### 3.1 建集合（8 个，名称必须逐字一致）

```
users  workorders  notices  phonebook  qa_feedback  qa_sessions  circle_post  service_category
```

> 少一个的表现：对应接口返回 500，前端降级到本地常量/空态——不会崩，但功能没了。

### 3.2 建索引（4 个必需的）

| 集合 | 索引 | 为什么必须 |
|---|---|---|
| `users` | `accountId` **唯一索引** | 并发建档会撞号，应用层查重挡不住 |
| `service_category` | `key` **唯一索引** | 分类重复会渲染两次 |
| `notices` | `status + publishAt`（降序） | 列表主查询 |
| `circle_post` | `status + publishAt`（降序）、`type + status + publishAt` | 列表 + 类型筛选 |

> `notices` 的 `type + endAt` 索引：演示数据 ≤20 条，慢查询概率低，可后补。

### 3.3 配权限（8 条规则摘要）

| 集合 | 读 | 写 |
|---|---|---|
| `users` | 本人 + 管理员（展示字段对外可读） | 本人 + 管理员 |
| `workorders` | 本人 + 物业/管理员 | 本人创建，物业可改状态 |
| `notices` / `phonebook` | 所有人 | 仅管理员 |
| `qa_feedback` | 管理员统计 | 本人 |
| `qa_sessions` | **仅本人**（`_openid` 隔离） | 本人 |
| `circle_post` | 所有人（`status=published`） | 仅管理员（本期禁 UGC 直写） |
| `service_category` | 所有人（`status=online`） | 仅管理员 |

> `qa_sessions` 若配成"所有人可读"，等于把居民的问诊对话公开。**这条必须逐字对。**

### 3.4 配环境变量（6 个）

| 变量 | 不配的后果 |
|---|---|
| `DEEPSEEK_API_KEY` | AI 走 kb 降级回答——**这是设计内降级，不是故障** |
| `PHONE_AES_KEY` | 号码加密相关功能不可用 |
| `SUBSCRIBE_TEMPLATE_WORKORDER_DONE` | 订阅消息静默跳过，不报错 |
| `CCF_FORCE_MOCK` / `CCF_MOCK_NO_SEED` | 云函数内的 mock 开关，真环境应**不设或设 false** |
| `TCB_ENV` | 云开发自动注入，通常无需手工配 |

> 配了 `CCF_FORCE_MOCK=1` 却以为是真数据，是这类项目最常见的"假联调"。上传前确认这两个没被设上。

### 3.5 导入种子数据

```bash
node scripts/seed.mjs          # 生成 scripts/seed-data.json（已被 gitignore）
node scripts/selftest.mjs      # 本地 mock 通道自检：167/167
```

然后到云开发控制台 → 数据库 → 对应集合 → 「导入」选 `scripts/seed-data.json`。

> **演示红线**：紧急通知的 `startAt/endAt` 是**相对时间**（now ± Nd）生成的。
> 10-23 打包前必须**重跑 `seed.mjs` 并重新导入**，否则演示当天显示"已过期"空态。

### 3.6 上传 8 个云函数

IDE → 云开发 → 云函数 → 逐个右键「上传并部署：云端安装依赖」。
**必须选"云端安装依赖"**，否则本地的 `node_modules`（Linux/mac 二进制）会被打成包上传，云端跑不起来。

验证：云开发控制台 → 云函数 → 每个函数「测试」，用 `{"action":"list"}` 之类跑一次，看返回 `{code:0}`。

## 8. 通道口径（CR-017-b，容易被忽略但会被追问）

> "所有契约一致性结论、接口验收、端到端断言，必须在 `USE_MOCK = false` 的通道下取得。
> **mock 通道下的「全绿」不构成任何契约验收证据。**"

所以：

| 结论 | 通道 | 能否作为验收证据 |
|---|---|:-:|
| `npm run verify` 201 条全绿 | 前端单测（无通道） | ✅ 前端逻辑 |
| `node scripts/selftest.mjs` 167/167 | **mock** | ❌ 只证明后端逻辑，不证明云端分发 |
| 第 4 节 7 条冒烟 | **真云** | ✅ 唯一有效证据 |

答辩时若被问"你怎么证明接口是通的"，**只能拿第 4 节的记录**，不能拿 167/167。
