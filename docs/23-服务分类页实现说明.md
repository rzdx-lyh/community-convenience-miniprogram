## 2. 数据：10 项 → 38 项

`config/service-grid.ts` 从 4 类 / 10 子项扩到 **4 类 / 8 板块 / 38 子项**，名称与设计原型逐项对齐。

```ts
export const LOCAL_SERVICE_CATEGORIES = withFlattenedItems([...]);
```

**关键设计：`groups` 是结构，`items` 是派生。**

```ts
function withFlattenedItems(list: ServiceCategory[]): ServiceCategory[] {
  list.forEach((category) => {
    const flat: ServiceItem[] = [];
    (category.groups ?? []).forEach((group) => flat.push(...group.items));
    category.items = flat;
  });
  return list;
}
```

为什么不手写两遍：办事大厅的搜索（`buildHallRows`）读 `items`，分类页读 `groups`。如果两处各写一份，
**改了板块忘了改扁平列表**，就会出现"分类页有、搜不到"。用函数派生，物理上不可能不同步。

> 自测里有一条正向对照：`items` 的 key 集合必须严格等于 `groups` 展平后的 key 集合。

## 3. 路由：零新增 targetType

契约的 `targetType` 只有 6 种（page / notice / circle / assistant / phone / toast），我没有加第 7 种。

| 服务类型 | 走哪 | 数量 |
|---|---|:-:|
| 需预约登记（家政 6 + 助浴/陪护/改造/家医） | `page` → 本页自身 + `targetParams.book`，**页内弹层** | 10 |
| 通知/活动（义诊、助餐、邻里活动、手机课） | `notice` + `{type, tag}` | 4 |
| 卫生站（社区门诊挂号） | `page` → `/pages/phonebook/index?category=medical` | 1 |
| 尚未建页的（缴费/生鲜/设备/租售/快递等） | `assistant` + 预置问句 | 23 |

**预约类为什么指向自己**：`targetParams.book` 存在时，点击**不调用** `navigateByTarget`，
直接开弹层。如果不拦这一下，`navigateTo` 会跳到本页自身，形成无限叠层。

**23 项走 AI 不是偷懒**：缴费、生鲜、租售、共享设备这些在代码里还没有页面，
`assistant` 是唯一合法承接方式，而且预置问句都写成了能实际回答的（如"共享雨伞怎么借？超时怎么收费？"）。

## 7. 自测（`tests/service-category.test.ts`，23 条）

这组断言的重点不是"函数算得对"，而是**数据不出死链**：

| 组 | 断言 | 抓什么 |
|---|---|---|
| 规模与结构 | 5 | 4 类 / 8 板块 / 38 项；key 唯一；每项有名称与说明 |
| **items 与 groups 同源** | 1 | 展平函数漏项 |
| **路由不出死链** | 3 | `targetType` 只用 6 种；**所有 `targetPath` 必须在 app.json 注册**；assistant 必须带问句 |
| 无死胡同 | 1 | 没有一项落到 `toast`（点了只弹"暂未开通"） |
| 预约参数 | 1 | 10 项带 `book`，`opts` 用 `|` 分隔且无空项 |
| 视图模型 | 5 | 有/无 groups 两种数据形态都能渲染；book 标记正确 |
| 纯函数 | 4 | `pickCategory` 回退、`countItems` 合计 38、`initialOfName` 降级 |
| 提交文案 | 2 | 字段顺序固定；无选项/无备注不留空行 |
| 回查原始项 | 2 | 命中返回完整 `ServiceItem`；未命中不抛错 |

**「所有 targetPath 必须在 app.json 注册」这条最有价值**：38 项里任何一个路径写错，
真机上表现就是"点了没反应"，很难在测试阶段发现。用 `app.json` 做交叉校验，一次覆盖全部。

## 8. 踩到的坑

**① 重新生成数据文件时把三个导出弄丢了。** `GRID_ICON_TEXT` / `GRID_DECO_TEXT` / `firstItemOf`
被其它模块引用，删掉直接 `TS2305`。教训：**重写一个被 import 的文件前，先 `grep "^export"` 对齐导出面**。

**② 页面文件不能直接写测试。** 一 `import` 就会执行 `Page({...})`，vitest 里 `Page is not defined`。
按项目既有约定拆出 `viewmodel.ts`（index / repair-list 都这么做），页面只留 `Page()`。

**③ 版本守卫拦住了我。** 我在 `service-grid.ts` 注释里写了「与设计原型 v1.4.0 对齐」，
`tests/version.test.ts` 立刻失败——代码侧只允许出现 `v1.0.1`。
这不是误报，是它按设计工作：代码里出现别的版本号，迟早有人分不清哪个是真的。
