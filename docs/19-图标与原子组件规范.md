> 需求原文：`一些图标和组件可以换成阿里组件库`
> 交付物：`docs/03-preview/demo.html`（v1.2.0，唯一入口，历史路径已同步）
> 自测：功能回归 48 条 + 图标系统 29 条，**全绿**

---

## 1. 先对齐一个概念：阿里系有"图标库"和"组件库"两套东西

用户说的"阿里组件库"，落到工程上其实是两件事，这一版两件都做了：

| | 是什么 | 这次怎么落 |
|---|---|---|
| **图标** | 阿里巴巴矢量图标库 iconfont（iconfont.cn） | 83 枚内联 SVG symbol，**按 iconfont 的 Symbol 引用方式组织** |
| **组件** | Ant Design Mobile（支付宝/阿里系移动端组件规范） | 按钮 / 标签 / 单元格 / 开关 / 进度条 五种原子件按 ADM 规格重定 |

**为什么图标不用 CDN 字体**：原型是一个单文件 HTML，要能双击离线打开。`//at.alicdn.com/t/c/font_xxx.css` 加载不到就退化成方框（豆腐块），而且没有真实项目 ID 也拉不到。内联 symbol 的调用形态和 iconfont 完全一致：

```html
<!-- iconfont 的 Symbol 用法 -->
<svg><use xlink:href="#icon-home"/></svg>
<!-- 本项目的用法（零依赖） -->
<i class="ii"><svg viewBox="0 0 24 24"><use href="#ic-home"/></svg></i>
```

进小程序时把 `<use>` 换成 `<text class="iconfont">&#xe600;</text>` 即可，**调用处的名字不用改**。

## 2. 图标系统

### 2.1 规格

| 项 | 值 | 理由 |
|---|---|---|
| 网格 | 24 × 24 | iconfont / ADM 通用网格，缩放到 16/18/20/24 都清晰 |
| 描边 | 1.9px | 1.5 在小尺寸发虚，2.5 在 20px 显笨；1.9 是 16–24px 的舒适区 |
| 端点 | round cap / round join | 与圆角卡片、胶囊按钮的语言一致 |
| 颜色 | `currentColor` | **一处改色，图标自动跟随**；选中态不用另做一套彩色图标 |
| 填充 | 默认 `fill:none`，`.solid` 类切实心 | 星标等需要实心的单独给 |

```css
.ii{display:inline-flex;width:1em;height:1em;line-height:1;vertical-align:-.13em}
.ii svg{width:100%;height:100%;fill:none;stroke:currentColor;stroke-width:1.9;
        stroke-linecap:round;stroke-linejoin:round}
.ii.solid svg{fill:currentColor;stroke:none}
```

关键点：`fill`/`stroke`/`stroke-width` 都是**可继承属性**，会穿透 `<use>` 的 shadow tree —— 所以 83 枚 symbol 里**一个 fill 都不用写**，全靠外层 CSS 控制。

### 2.3 emoji → 图标映射（EMO2I）

数据层**没动**：38 个服务项的 `i:'🔧'` 原样保留，只在渲染边界换成矢量图：

```js
function iconName(e){
  var k = String(e).replace(/[\uFE0F\u200D]/g,'');   // 去掉变体选择符与 ZWJ
  return EMO2I[k] || EMO2I[e] || '';
}
function icoE(e, s){ var n = iconName(e); return n ? ico(n, s) : String(e); }
```

`icoE` 的**兜底是有意设计的**：查不到映射就原样输出 emoji。这样新加服务项不会因为忘了配图标而变成空白。

> 踩坑：`👨‍⚕️`（ZWJ 组合）、`❄️`/`☂️`/`✏️`/`⚠️`（带 VS16）在 JS 里长度不同，直接用等号比较查不到。必须先 `replace(/[\uFE0F\u200D]/g,'')` 归一化。

### 2.4 哪些 emoji 保留了（刻意的）

| 保留位 | 例子 | 理由 |
|---|---|---|
| 菜品图 | 🥣 🎃 🐟 🍤 | 这是**图片占位**，不是图标。换成线性图标后 15 道菜全长一样，反而更差 |
| 商品图 | 🥬 🍅 🥦 🥛 | 同上，生鲜列表需要色彩区分 |
| 房源/科室图 | 🏢 🏦 🧒 🌿 | 大图占位 |
| 帖子配图 | 🚧 🚲 🐱 🪑 | 用户内容，且带"示意配图"标注 |
| 用户原话 | 🙏 👍 🎉 | 帖子正文里的表情，属于内容 |
| 说明文案 | 🥗 📊 🔄 | 页面外的产品说明文字，不是 UI |

判定原则一句话：**它是在"指代一个动作/入口"（→ 图标），还是在"占一个图片的位置/表达情绪"（→ 保留 emoji）**。

## 3. 原子组件（Ant Design Mobile 规范）

### 3.1 按钮 `.abtn`

| 变体 | 类名 | 底/字 | 用在哪 |
|---|---|---|---|
| 主 | `.abtn-p` | 蓝底白字 | 页面唯一主行动 |
| 次 | `.abtn-d` | 白底蓝字蓝边 | 并列的次要选项 |
| 默认 | `.abtn-f` | 浅灰底深字 | 弱化操作 |
| 危险 | `.abtn-r` | 红底白字 | 撤销/删除 |
| 禁用 | `.dis` / `:disabled` | 36% 透明 + 屏蔽指针 | — |

尺寸三档：`40`（默认）/ `.abtn-l` 46（底部主按钮）/ `.abtn-s` 28（标签型）。
圆角 8，字号 14/600，`:active` 缩放 `.98` + 亮度 −5%。

> **`.btn2` 的覆盖陷阱**：demo 里底部固定条的按钮是 `.fbar .btn2`，特异性 0-2-0，比后写的 `.btn2`（0-1-0）高，所以光在文件末尾追加 `.btn2{height:42px}` **不生效**——必须同时追加 `.fbar .btn2{...}`。这类"后写不覆盖"的坑在单文件原型里非常常见。

### 3.2 标签 `.atag` / `.tag`

圆角 4（不是胶囊——胶囊留给筛选 chip，两者语义不同）。5 种语义：

| 类名 | 色 | 语义 |
|---|---|---|
| `.atag` | 蓝 | 办理中 |
| `.atag.g` | 绿 | 已完成 |
| `.atag.y` | 黄 | 待支付 |
| `.atag.r` | 红 | 已驳回 |
| `.atag.o` | 蓝描边 | 可选/未选中 |

### 3.3 单元格 `.acell`

最小高 48（手指可点），左侧 24px 图标槽、标题 14/500、描述 11.5、右侧箭头 17。`:active` 时底色 `#FAFBFC`。

这个组件替代了原来 `demo` 里散落的"图标 + 两行字 + 箭头"手写块——**同样的东西之前有 6 处各写一遍**，尺寸各不相同。

### 3.4 开关 `.asw` / 进度条 `.abar`

- 开关 44×26，滑块 22，行程 18px，开启色 `#1FA97A`（青绿，与"健康/设备"语义一致）
- 进度条高 6、圆角 99，宽度用 `transition` 平滑过渡

### 3.5 chip 微调

`.chip` 从 32px 收到 30px、圆角 8→6、字重降为 500，选中态加 1px 内阴影代替原来的纯色填充——避免整块色压住相邻内容。

## 4. 这一版**没有**做的事

用户上一轮刚提过"每个功能都差不多"，所以这轮**刻意只统一原子、不动骨架**：

| 保留 | 为什么 |
|---|---|
| P1–P6 六种页面骨架 | 统一骨架会立刻退回"每页都长一样" |
| 每页不同的沉浸头主色 | 每页主色是区分度的一部分 |
| 菜品卡的 emoji 图 | 换成线性图标会让 15 道菜失去辨识度 |

一句话：**图标和按钮要统一，页面结构不能统一。**

## 5. 自测

### 5.1 图标系统专项（`.workbuddy/_t12.mjs`，29 条全绿）

| 组 | 断言 | 抓的是哪类问题 |
|---|---|---|
| 资源完整性 | symbol 83 枚 · id 前缀统一 · 无重复 · **EMO2I 全部有对应图标** | 映射写错 → 渲染成空白 |
| 全页断链 | 21 个页面渲染出的 `<use>` **全部可解析**，累计 271 处 | 引用了不存在的 symbol → 静默空白 |
| 导航宫格 | tabbar 4 项有图标且文字未被顶掉 · 宫格 38 项全矢量化 · 首页零功能 emoji | 图标盖住文字 |
| 残留 emoji | 逐页扫描，只允许图片/内容类 | 漏改 |
| 组件库 | 83 格图标墙 · 四态按钮 · 5 标签 · 单元格 · 开关 · 进度条 | 组件没真渲染 |
| 样式生效 | `.btn2` 实测 42px/600 · `.ii svg` 实测 stroke 1.9 · stroke ≠ none | **写了 CSS 但被覆盖** |

最后一条是这轮唯一抓到的真 bug：`.fbar .btn2` 特异性比追加的 `.btn2` 高，实测是 40px/800 —— 靠 `getComputedStyle` 才发现，肉眼看不出 2px 差异。

### 5.2 功能回归（`.workbuddy/_t11.mjs`，48 条全绿）

图标替换动了 40+ 处模板字符串，重点回归了：圈子 9 帖、办事 4 tab、AI 页、预约向导 3 步、配餐全流程。

### 5.3 踩到的 3 个语法坑

| 现象 | 原因 | 修法 |
|---|---|---|
| `SyntaxError: Unexpected identifier 'pin'` | `${ico('pin',12)}` 写进了**单引号字符串**（`'<span class="ic2">...</span>'`），不是模板字符串 | 改成 `'...'+ico('pin',12)+'...'` |
| `missing ) after argument list` | 同上，`'<div class="ph">${ico(...)}</div>'` 里嵌套了同款引号 | 抽出成字符串拼接 |
| 测试报 8 个 `.k` 未矢量化 | `.k` 里还有"紧急/公告/活动"三枚**标签型**格子，本来就不该有图标 | 断言里过滤掉含 `.tag` 的 `.k` |

结论：单文件原型里做批量替换，**必须抽 `--check` 语法校验**，不能只靠"页面看起来正常"。

## 6. 小程序落地映射

### 6.1 图标

1. 在 iconfont.cn 建项目，把这 83 枚按同名上传（或用现有图标库挑同义的）
2. 下载 `iconfont.css` + `iconfont.ttf` 放进 `miniprogram/assets/iconfont/`
3. `app.wxss` 引入 `@font-face`，全局 `.iconfont{font-family:"iconfont";font-size:...}`
4. 把 `ico(name)` 换成 `<text class="iconfont icon-${name}"></text>`

因为原型已经把所有图标收敛到 `ico()` / `icoE()` 两个函数，**迁移只改这两个函数体**，40 多处调用点一行都不用动。这是这轮重构最大的工程价值。

### 6.2 组件

- `.abtn` → 自定义组件 `components/ui/btn`
- `.acell` → `components/ui/cell`
- `.asw` → 用原生 `<switch>` 换色（wxss 改 `switch .wx-switch-input`）
- `.abar` → `components/ui/progress`
- 也可以在 `app.json` 里用 `"usingComponents"` 引 `antd-mini` 的按需组件（注意 antd-mini 原生面向支付宝小程序，微信需走 `mini-antui` 或自行移植）
