## 1. 结论先行

建议采用：

> **同一个微信小程序 + 两套相互隔离的端内入口与页面壳层**。

- 默认进入 **客户端**；
- 客户端通过微信静默登录/首启资料设置进入；
- 启动登录页提供「居民/家长」和「社区工作人员」两个入口；
- 社区工作人员通过 **管理员账号 + 密码** 登录后台管理端；
- 后台登录成功后进入独立的管理页面体系；
- 管理端与客户端共用同一套用户、工单、通知、电话簿和 AI 能力；
- 服务端必须再次校验管理员身份，不能只依赖前端页面跳转。

首期建议不做两个独立小程序，原因：

1. 需要复用同一批用户、工单、通知、电话簿和 AI 服务；
2. 双 AppID 会带来数据同步、发布审核、登录体系双份维护；
3. 当前工程已有 `resident / property / admin` 角色基础，可在原工程上升级；
4. 单小程序内做安全隔离，已能满足社区规模的管理需求。

如果后续后台出现大量表格、批量导入导出、复杂统计和多角色审批，再增加独立 Web 管理后台。

## 2. 建设目标

### 2.1 客户端目标

主要服务两类人群：

#### A. 18 岁之前的青年、学生和儿童

关注点：

- 社区活动、志愿服务、四点半课堂；
- 学习与办事指引；
- 安全求助和风险上报；
- 公共设施问题反馈；
- 社区通知和活动报名；
- 适合未成年人阅读的简明界面；
- 监护人可见、可控。

#### B. 60 岁以后的独居老人

关注点：

- 大字号、强对比、低操作成本；
- 一键拨打物业、社区、卫生服务站和紧急电话；
- 助餐、助浴、上门维修、健康测量、就医陪护；
- 关怀模式默认开启；
- 可绑定家属代下单；
- 紧急联系人；
- 不使用复杂搜索和多层级菜单。

### 2.2 管理端目标

主要服务社区工作人员、物业人员和社区管理员：

- 用户与家庭档案管理；
- 青少年/长者标签与重点关怀名单；
- 报修工单派单、处理、完成、回访；
- 通知、活动、电话簿和服务分类维护；
- 圈子内容审核与举报处理；
- AI 问答反馈和知识库维护；
- 数据统计、导出和审计；
- 管理员账号、权限和操作日志管理。

## 3. 双端形态设计

### 3.1 推荐形态

```text
微信小程序启动
      │
      ▼
统一启动/登录页
      │
      ├── 居民/家长入口（默认）
      │       │
      │       ▼
      │   微信身份识别
      │       │
      │       ▼
      │   首启资料/用户类型设置
      │       │
      │       ▼
      │   客户端首页
      │
      └── 社区工作人员入口
              │
              ▼
        管理员账号 + 密码
              │
              ▼
        管理员会话校验
              │
              ▼
        后台管理首页
```

### 3.2 登录页建议

登录页使用两个页签：

```text
[ 居民 / 家长 ]    [ 社区工作人员 ]
```

- 默认选中「居民 / 家长」；
- 点击「社区工作人员」后才显示账号、密码输入框；
- 不在客户端首页放明显的后台入口；
- 管理员退出登录后回到该登录页，并恢复默认客户端页签；
- 后台登录失败必须有频率限制和账号锁定；
- 不允许通过 URL 直接进入后台页面。

### 3.3 双端隔离

引入统一的 `portalMode`：

```text
client | admin
```

规则：

- 首次安装默认 `client`；
- 普通用户无法通过修改本地存储获得后台权限；
- 后台页面进入前同时检查：
  1. 本地 portalMode；
  2. 管理员会话是否有效；
  3. 服务端角色是否具备后台权限；
- 服务端不信任前端传入的 `role`、`isAdmin` 或 `portalMode`。

## 5. 首启资料流程

### 5.1 客户端

默认走微信身份识别，不要求输入账号密码。

首启流程建议：

1. 微信隐私协议确认；
2. 选择使用身份：
   - 我是学生/孩子；
   - 我是长者；
   - 我是普通居民；
   - 我是家属/监护人；
3. 填写昵称、头像、楼栋位置；
4. 根据身份补充最少信息；
5. 进入客户端首页。

### 5.2 未成年人流程

若选择「我是学生/孩子」：

- 不以精确生日作为公开资料；
- 可只保存 `ageGroup = youth` 或出生年份；
- 显示「需要监护人同意」；
- 提供监护人绑定码或监护人手机号验证；
- 未完成监护人确认前：
  - 不开放私聊；
  - 不开放公开个人主页；
  - 不开放金额交易；
  - 活动报名需监护人确认。

### 5.3 长者流程

若选择「我是长者」：

- 自动建议开启关怀模式；
- 可选择「独居/与家人同住/不便公开」；
- 「独居」只用于内部关怀，不在公开圈子展示；
- 设置紧急联系人；
- 可绑定家属代为预约和接收通知；
- 进入首页时优先展示：
  - 一键电话；
  - 助餐；
  - 健康服务；
  - 报修；
  - 紧急求助。

### 5.4 管理员首次登录

管理员账号不能通过普通注册页面创建。

建议方式：

- 首个超级管理员由部署脚本或云控制台写入；
- 密码使用 `scrypt` 或 `bcrypt` 加盐哈希；
- 首次登录强制修改初始密码；
- 后续管理员由超级管理员创建；
- 管理员账号与微信 openid 可选绑定，但账号密码仍是后台入口凭证。

## 11. 安全与合规

### 11.1 账号安全

- 管理员密码必须加盐哈希；
- 禁止在数据库、日志和源码中保存明文密码；
- 连续登录失败 5 次锁定 15 分钟；
- 管理员登录接口限流；
- 会话有效期建议 2 小时，可续期；
- 退出登录立即销毁会话；
- 管理员可强制下线；
- 所有敏感操作记录审计日志。

### 11.2 未成年人保护

- 未满 18 岁用户必须获得监护人同意；
- 不公开展示未成年人真实姓名、学校、联系方式；
- 不提供陌生人私聊；
- 活动报名可要求监护人确认；
- 内容发布经过安全检查；
- 建立举报与快速下架机制。

### 11.3 长者隐私

- 「独居」标签不对其他居民公开；
- 紧急联系人信息加密或严格脱敏；
- 仅授权工作人员可查看完整联系方式；
- 查看和导出均记录审计日志。

### 11.4 隐私保护指引

在微信后台同步更新：

- 账号信息；
- 头像/相册；
- 用户主动填写的楼栋和联系方式；
- 监护人关系；
- 紧急联系人；
- 服务记录；
- 不声明未使用的定位接口。

## 12. 客户端体验建议

### 12.1 青少年

- 明亮、简洁的卡片；
- 任务式入口；
- 活动报名与志愿时长；
- 安全求助按钮；

- 关怀模式默认开启；
- 正文不小于 44rpx；

## 14. 验收标准

### 客户端

- 新用户默认进入客户端；
- 未登录普通用户无法进入管理端；
- 未成年人未绑定监护人时限制高风险功能；
- 长者开启关怀模式后全局字号和点击区域正确放大；
- 首页服务分类、按钮和色块无错位；
- 所有核心页面无横向溢出。

### 管理端

- 账号密码登录成功；
- 错误密码受频率限制；
- 普通居民无法调用管理接口；
- 管理员只能查看权限范围内数据；
- 工单、通知、用户操作可审计；
- 退出后不能通过返回键重新进入后台。
