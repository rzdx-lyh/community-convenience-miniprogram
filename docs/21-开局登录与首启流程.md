# 21 · 开局登录与首启流程（v1.3.1）

> 需求原文：`增加一个开局用户登录`
> 交付物：`docs/03-preview/demo.html`（v1.3.1）
> 自测：功能 48 + 图标 29 + 我的页 66 + 登录 56 = **199 条全绿**

---

## 1. 为什么这一步重要

改之前，demo 打开就是首页宫格。问题不在好不好看，而在**它看起来不像一个小程序，像一个页面合集**：

- 没有身份来源——"阿明的小院"从哪来的？
- 没有授权动作——真实小程序第一屏必然是登录/授权
- 没有协议同意——个人信息处理没有合法基础
- 评审点开第一眼，很难相信这东西能过审

补上第一屏之后，整个 demo 从"页面展示"变成"产品流程"。

---

## 2. 流程

```
打开
 └→ 登录页（P7 授权型）
      ├ 未勾协议 → 抖动 + 变红 + toast，不放行
      ├ 手机号登录 → 如实提示"个人主体未开放"
      ├ 点《用户协议》《隐私政策》→ 弹层读全文
      └ 勾选 + 微信一键登录 → 700ms loading
           └→ 完善资料页
                ├ 昵称 2-12 字（预填，可改）
                ├ 头像 8 色
                ├ 楼栋房号 + 「一键按定位填写」
                └ 进入社区 → 首页
```

`state.auth` 三态：`'login'` → `'welcome'` → `'done'`。渲染入口一道门禁：

```js
const authed = state.auth === 'done';
const show = authed && tabs.indexOf(state.page) >= 0;   // 登录前隐藏底部导航
$('#screen').innerHTML = authed
  ? (map[state.page] || pgHome)()
  : (state.auth === 'welcome' ? pgWelcome() : pgLogin());
```

**为什么用"门禁"而不是"弹层"**：一张半透明遮罩能挡点击，但挡不住信息泄漏——未登录时首页内容仍然渲染在 DOM 里。改成路由级门禁，未登录状态下**屏幕里根本没有首页的 DOM**，这才是真拦住。

## 3. 登录页（P7 授权型）

新增第 7 种页面原型。它和前 6 种的区别：**用户还没进入产品，需要先被"说服 + 授权"**。

```
┌─────────────── 渐变色块（占屏 1/3）
│       [猎]  ← 62px 圆角方块 logo
│   猎奇便民服务
│   阳光社区 · 报修缴费挂号，一个入口办完
│
│    38        8        24h
│  项服务   个板块   自助办理
├─────────────── 白卡（-32px 压上来）
│   登录后即可预约、报修与发布
│  ┌─────────────────────────┐
│  │ ⬤ 微信一键登录            │   ← 22px 微信绿圆 + 蓝主按钮
│  └─────────────────────────┘
│       手机号登录
│    个人主体无法获取手机号，当前版本未开放
│
│  ☐ 我已阅读并同意《用户协议》和《隐私政策》
│
│  🔒 仅收集办事必需信息：昵称、楼栋房号、联系方式…
└─────────────── v1.3.1 · 猎奇小分队 · 演示原型
```

**三个数字是"卖点"不是装饰**：38 项服务 / 8 个板块 / 24h 自助办理——用真实数据回答"这个 App 有多少东西"。

**微信一键登录的绿色圆**：整体是政务蓝体系，但"微信授权"在国内是强约定俗成的绿色（微信官方按钮就是 `#07C160`）。折中做法是**按钮保持主题蓝，只在图标位放一个 22px 的微信绿圆**——既有识别度，又不破坏设计系统。

## 4. 协议同意：这次做的是"真拦截"

这是整页最该认真做的地方，也是评审最容易挑刺的地方。

| 要求 | 实现 |
|---|---|
| 默认不勾选 | `state.agree=false`，勾选框空白 |
| 未勾选不能登录 | 点登录 → `toast('请先阅读并勾选同意协议')` + 勾选框抖动 + 变红 |
| 不能静默失败 | 抖动的目的是让用户**看见是哪里出了问题**，而不是只弹一句话 |
| 每次回登录页重置 | 工具栏「登录页」按钮会把 `agree` 置回 false，防止"上次勾过就永久放行" |
| 协议可读 | 点标题进弹层，写了真实条款 |

**抖动动画**（`.shk` + `@keyframes shk`）比单纯 toast 有效：视线会被移动的东西吸引，用户立刻知道该点哪里。

### 协议正文写了什么

**用户协议** 4 条：服务性质（不收款/不担保/不诊断）、账号（一微信一账号、不得转让）、发布规范（禁广告涉政谣言与他人隐私）、免责（转让纠纷自担、急病拨 120）。

**隐私政策** 5 条：收集什么、用来做什么（不外画像不推广告）、位置（只读一次不存轨迹）、健康数据（仅本人与签约医生）、你的权利（改资料/关通知/注销）。

> 弹层底部明确写：**"以上为演示摘要，正式上线前需由法务出全文并经微信审核。"** 不假装这就是终版法务文本。

## 5. 手机号登录为什么写成"未开放"

个人主体小程序**拿不到手机号**：`getPhoneNumber` 只对已认证的企业/组织主体开放，且按次收费。

三种处理方式：

| 做法 | 评价 |
|---|---|
| 不放这个入口 | 界面上少一条"行业标配"，但最干净 |
| 放了但点了报错 | **骗人**，评审一点就露馅 |
| 放了并如实标注"个人主体未开放" | ✅ 采用 |

明确写"为什么没有"比隐藏更专业——它证明你知道这条限制的存在和原因。

## 6. 完善资料页

```
┌ ‹ 完善资料                1 / 1
│  ┌──┐ 欢迎加入阳光社区
│  │阿│ 资料用于社区内展示与上门服务定位
│  └──┘
│ 昵称  2-12 字，邻居会看到
│ [阿明的小院              ]
│ 头像底色
│ ● ● ● ● ● ● ● ●        ← 8 色，选中态外圈同色
│ 楼栋房号  上门服务定位用
│ [3 号楼 2 单元 502   ] [📍 自动]
│ 房号只用于上门定位，不对其他居民公开
├────────────────────────────
│ 阿明的小院 / 3 号楼 2 单元 502   [进入社区]
```

三个设计点：

1. **昵称预填而不是空的**——演示时评审不用打字就能一路点下去。真实产品这里应该是空 + 引导语。
2. **「📍 自动」按钮**复用地图页的定位结果，直接填 `3 号楼 2 单元 502`。把已有能力串起来，比凭空多一个输入框有价值。
3. **底部固定条实时预览**——输入昵称/房号，底部条立刻跟着变，用户知道自己填成了什么。

校验：昵称 < 2 字拦截、房号为空拦截，两个都 toast 且停在原页。

## 7. 登录结果要"真的生效"

如果登录页填的昵称只存在登录页里，那就是走个过场。这次三处都穿透了：

| 位置 | 表现 |
|---|---|
| 首页 | 顶部问候使用 `state.prof.name` |
| 圈子 | 我发的帖子作者名与头像走 `dispWho()` / `dispAv()` |
| 我的页 | 昵称、头像字、头像色、房号全部同步 |

复用了 v1.3.0 建立的 `ME_SEED` + `dispWho()` 机制，所以**改名不会破坏「我发的」筛选**（筛选用固定标识，只有显示层替换）。

自测第 9 组专门验这个：登录填「阿明家的院子」后，切到圈子看作者名、切到我的页看昵称，两处都必须变。

## 8. 草稿保护的第三次踩坑记录

「完善资料」页换头像颜色会 `render()`，因此重渲染前必须把输入框内容写回 state：

```js
if(a==='welcome-color'){
  state.prof.color = el.dataset.v;
  const n=$('#welcomeName'), ad=$('#welcomeAddr');
  if(n) state.prof.name = n.value;      // ← 不写这两行，换颜色就丢昵称
  if(ad) state.prof.addr = ad.value;
  render(); return;
}
```

这是本项目**第三次**踩同一个坑（前两次：预约向导、家庭成员弹层）。已写进项目记忆的通用规则：

> **任何会触发 `render()` 的点击，都要先把用户输入收进 state；重置草稿的逻辑放在 `openXxx()` 里，不要放在 `sheetXxx()` 里。**

自测里为此专门加了断言「换头像色后昵称不丢」。

第 10 组的「回登录页后仍然被拦」是我特意加的：很多实现会写成"勾过一次就一直放行"，这在合规上是错的——每次进入登录都应重新确认。

### 三套旧测试的连带修改

加了门禁后，旧测试（t11/t12/t13）打开就是登录页，会全部失败。处理方式：每套在 `await sleep()` 后加一行放行：

```js
ev(`state.auth='done';state.page='home';render();`);
```

同时把 t13 里写死的 `v1.3.0` 断言改成 `ev('APP_VER')`——**测试不该硬编码版本号**，否则每次升版都要改测试，迟早会有人为了过测试去改产品。

## 10. 小程序落地要点

| 项 | 做法 |
|---|---|
| 静默登录 | `wx.login` → code → 云函数换 `openid`，作为账号主键，**不需要用户点任何按钮** |
| 显式授权 | 只有要昵称头像时才 `chooseAvatar` + `input type="nickname"`（新版规范，需用户主动触发） |
| 协议同意 | 勾选状态存 `storage`，并记录同意时间与版本号（合规留痕）；**协议更新后要求重新同意** |
| 手机号 | 个人主体不可用；若将来主体升级，再开 `getPhoneNumber` |
| 楼栋房号 | 社区场景必需，建议做成「楼栋 / 单元 / 房号」三级 picker，比自由输入准确 |
| 首启引导 | `app.json` 里用 `entryPagePath` 指向登录页；已登录（有 openid 缓存）直接跳首页 |

**建议的正式实现顺序**：先 `wx.login` 静默拿 openid（无感），再判断是否首次登录；首次才展示「完善资料」，老用户直接进首页。这样老用户永远不会被登录页挡一次——这也是真实小程序的通行做法。
