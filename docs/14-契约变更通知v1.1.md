## 一、这次为什么改

原契约（v1.0）的 `qa:ask` 是**无状态**的——入参只有 `{question, elderMode}`，没有会话 ID，数据库里也没有会话表。

但测试用例已经这么写了：

| 用例 | 要求 | v1.0 下能否通过 |
| --- | --- | --- |
| TC-44 | 问"物业费怎么交"→追问"能网上交吗"，**多轮上下文连贯** | ❌ 不可能 |
| AIQ-20 | **会话内上下文一致**，不混乱 | ❌ 不可能 |
| TC-29 | 历史按会话保存，**可查看/清除** | ❌ 不可能（且没有对应接口） |

**无状态接口产生不了多轮。** 这不是实现问题，是契约缺失——现在补上，避免你做到一半发现验收过不了。

## 二、你受影响的部分

### 🔴 同学 A（前端）—— 影响 FE-2 AI 助手页

**`qa:ask` 出入参变了：**

```diff
  入参
- { question: string, elderMode?: boolean }
+ { question: string, elderMode?: boolean, sessionId?: string }

  出参
- { answerId, answer, sources[], degraded }
+ { answerId, sessionId, answer, sources[], degraded }
```

**你必须做**：
1. 收到 `sessionId` 后**缓存**（`storage` 或 `store`）
2. 后续每次提问**回传** `sessionId`
3. 不传 = 每次都是新会话 = TC-44 直接挂

**新增两个接口**（AI 助手页的历史记录）：

| 接口 | 入参 | 出参 |
| --- | --- | --- |
| `qa:history` | `{ sessionId?, page?, pageSize? }` | `{ list: QaTurn[], total }` |
| `qa:clear` | `{ sessionId? }` | `{ ok: boolean }` |

**其他不变**：错误码仍用契约那 8 个；`qa:suggest`、`qa:feedback` 完全不变。

### 🔴 同学 B（后端）—— 影响 BE-6

**新增集合**（`db-schema.md`）：

```
qa_sessions
├─ _id / _openid
├─ sessionId     string   会话 ID
├─ turns         array    QaTurn[]，服务端只保留最近 3 轮
├─ turnCount     number   累计轮次（用于统计，不受保留策略影响）
├─ createdAt / updatedAt  ISO8601
索引：_openid + sessionId（唯一）、updatedAt
权限：仅本人可读写；管理员只读统计，不可读 turns 内容
```

**上下文压缩规则（硬性，不写会让 token 爆）**：

| 规则 | 值 |
| --- | --- |
| 保留轮次 | 最近 **3** 轮 |
| 单条 content 上限 | **300 字** |
| 总上下文上限 | **2000 tokens**（估算），超限丢弃最早轮次 |
| 会话过期 | 最后活动后 **2 小时** |

**顺带三项增强**（都写进 BE-6 验收了）：

1. **输入护栏**：空输入 / 超长 / 提示注入 / 非社区域问题 → 拦截，**不调用大模型**（省钱）
2. **未命中阈值**：检索最高分 < 1.0 → 判定未命中，直接兜底话术 + 便民电话，**不调用大模型**
3. **输出护栏**：回答里的电话 / 政策 / 金额必须命中知识库，否则替换原文或降级

**知识库位置定稿**（原来三处说法不一致，现在定了）：

```
cloudfunctions/shared/kb/kb.json      ← 就是这里，不是数据库集合
```

理由：规模小、变更少、免接口免权限、改完重新部署即生效、**能进 git 做版本管理**。
`qa_feedback` 集合**收敛为纯反馈表**，不要再往里塞知识库条目。
