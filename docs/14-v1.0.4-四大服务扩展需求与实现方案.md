## 3. 各板块落地形态

### 3.1 生活基础服务 › 家政服务（6 项）
保洁、家电维修、管道疏通、保姆/钟点工、开锁换锁、空调清洗。
认证信息挂在板块标题下：**认证师傅 · 明码标价 · 乱收费全额退款**（对应设计稿的三个勾选项）。
落地形态：全部走「预约登记」，不预付。

### 3.2 生活基础服务 › 缴费代办（3 项 + 3 个状态位）
水电燃气代缴 / 快递代取代寄 / 政务事项代办；底部固定三格：**户号绑定（已绑 2/3）· 驿站状态（开放中）· 办理进度（2 件办理中）**。
落地形态：**只绑户号 + 登记代缴 + 展示进度**，钱在微信「生活缴费」里付。

### 3.3 生活基础服务 › 生鲜零售（4 项）
当日鲜菜 / 临期特惠 / 邻里拼单 / 次日自提 + 通栏「30 分钟配送到家 · 满 39 元免配送费」。
落地形态：**社区团购预订**（约到点、到点取），不做购物车、不做支付。

### 3.4 健康养老服务 › 基础健康服务（6 项）
社区门诊挂号（→ 取号）、义诊活动（→ 通知列表）、疫苗预约、健康档案（→ AI 问答）、免费测血压血糖（→ 时间地点弹层 + 可转预约）、体检报告代取。

### 3.5 健康养老服务 › 老年专属服务（6 项）
慢性病咨询（→ AI 问答）、助餐、助浴、上门陪护、适老化改造、家庭医生签约。
顶部 banner：**健康一键约 · 家人可代办**，右侧「预约记录」；表单里有「帮家人代办」开关。

### 3.6 便民配套服务 › 便民工具（3 类）
共享雨伞 / 应急维修工具 / 共享充电宝，每类都带 **扫码借用 · 异地归还 · 到期提醒**，配点位分布示意图。
落地形态：借用弹层 → 借用成功（编号 + 归还截止 + 逾期计费）→ 到期提醒开关。

### 3.7 便民配套服务 › 物业延伸（3 项 + 8 个二级入口）
- 外卖代收：设置存放点 / 预约上门取件
- 流浪动物管理：养宠专区 / 文明养宠公约 / 救助申请
- 房屋租售：真实房源 / 业主发布 / 求租求售

落地形态：信息登记与展示，**社区不做中介、不收佣金、不代收租金**。

1. **首页**：「常用服务」8 宫格 → 改为**四张服务分类卡**（2×2），每卡 3 个标签 + 箭头，与真实小程序的四类结构对齐。

3. **预约登记页**（新增 `pages/service/form`，**一个页面服务 37 个服务项**）：服务项目（只读带入）→ 期望时间（4 档）→ 楼栋（4 档）→ 房号 → 联系人 → 帮家人代办 → 备注 → 提交 → 回执（受理号 SQ+9 位 + 4 步进度）。
4. **弹层**：户号绑定、驿站状态、代办进度、设备借用/归还、养宠、租售、测血压血糖。

6. **AI 管家**：命中服务项时回「这个我能直接帮你约」+「直接去办」，点了直接落到预约登记页；问缴费时回「缴费走缴费代办」+「去绑定户号」。

## 5. 小程序落地要点（待实施）

### 5.1 类型扩展
`ServiceCategory` 增加一层 `groups`，避免把 37 项平铺：

```ts
interface ServiceGroup {
  key: string;            // housekeeping / bill / fresh / health / elder / tool / ext / culture
  name: string;           // 家政服务
  note?: string;          // 认证师傅 · 明码标价 · 乱收费全额退款
  render: 'grid' | 'bill' | 'fresh' | 'tools' | 'ext';
  sort: number;
  items: ServiceItem[];
}
interface ServiceCategory {
  key: 'life' | 'elder' | 'support' | 'culture';
  // …原有字段保留
  groups: ServiceGroup[];  // 新增；items 保留兼容（= groups 扁平化）
}
```

> ⚠️ `items` 必须保留并继续由 `groups` 派生，否则首页 `firstItemOf()`、旧版 `service:list` 契约会断。

### 5.2 新增页面
| 页面 | 路径 | 说明 |
|---|---|---|
| 分类详情 | `pages/service/category` | `?key=life`，按 `render` 切换板块样式 |
| 预约登记 | `pages/service/form` | `?cat=&grp=&item=`，一个页面覆盖全部登记类服务 |

### 5.3 新增集合 / 云函数动作
- `service_lead`：预约登记单（`svc/cat/grp/slot/unit/room/phone/proxy/note/status`）
- `service:lead:create` / `service:lead:list`（挂在现有 `service` 云函数下，按 `action` 分发）
- 缴费户号绑定若要做，需单独 `utility_account` 集合 + 加密存储，**本期可只做前端示意**

### 5.4 不能真做的部分（必须保留免责）
- 生鲜：无冷链、无库存、无支付 → 只做「预订登记」
- 租售：属房地产经纪，个人主体不可经营 → 只做「信息登记 + 展示」
- 共享设备：需硬件与物业合同 → 只做「借用登记 + 到期提醒」示意
- 代缴：涉资金 → 只做「户号绑定 + 进度」

## 6. 合规红线（答辩/备案要说清）

1. **个人主体**备案类目只能报「工具」，所以全部服务止步于**信息与预约**，页面上不出现「购买/支付/下单」字样。
2. 生鲜、租售、共享设备属**经营行为**，页脚必须有边界说明（原型已加）。
3. 健康类只做预约，不出具任何诊断或用药建议；急症仍走 120 兜底。
4. 证照亮证、政策计算器仍需实名授权，答辩不能说「已对接」。
