# 页面原型体系：为什么每个服务页该长得不一样

> 版本 v1.0.9 ｜ 交付 `docs/03-preview/demo.html`（唯一稳定入口）
> 起因：用户反馈「感觉页面的每个功能都差不多」

---

## 一、问题诊断

这不是配色问题，是**骨架复用过度**。改之前 8 个二级页是同一套：

```
导航栏 → 提示条 → 白卡（label + 字段）→ 一排「更多入口」列表卡 → 页面内蓝色按钮
```

证据：`缴费 / 快递 / 租售 / 健康档案` 四个页面的收尾都是同一个结构 ——
一个 `.blk` 里塞 2~3 个 `.row`（"快递代取代寄 / 政务事项代办"、"业主发布房源 / 我要求租求售"、"预约下次测量 / 问 AI 报告怎么看"）。
用户连续划 4 个页面，看到的都是「白卡 + 一排箭头」，自然会觉得"都一样"。

---

## 二、判断依据：骨架由「用户要做的判断」决定

| 用户在做什么 | 骨架 | 理由 |
|---|---|---|
| 要选好几项才能提交 | **P1 向导型** | 一屏只问一件事，进度可见，不会填到一半不知道还剩几步 |
| 只要核对一个数字 | **P2 票据型** | 取件码/单号是唯一要看的，就该最大 |
| 要看趋势和异常 | **P3 数据型** | 数字要有参照物（折线、正常区间），单列数值没有信息量 |
| 要在多个同类里挑一个 | **P4 卡片流** | 每项都要能被比较：图片、占比、价格对齐 |
| 要确认一个东西现在什么状态 | **P5 设备型** | 状态是圆环的时间比例，不是一行文字 |

---

## 三、五种骨架规格

### P1 向导型 Stepper
- 顶部三段进度条：`① 服务类型 — ② 时间 — ③ 地址确认`，完成变绿打勾
- 一屏一步：第 1 步只出选项卡，第 2 步只出日期+时段，第 3 步只出地址+摘要
- 底部 `.fbar` 浮动操作条：左侧摘要（已选什么 / 第几步），右侧主按钮
- **未选完不给过**：没选类型点"下一步"→ toast 拦截
- 用在：家政 6 项、助餐、助浴、上门陪护、适老化改造、疫苗预约

### P2 票据型 Ticket
- 31px 等宽大号取件码，字距 2.5px，`tabular-nums`
- 中间 `1px dashed` 齿孔线 + 卡片两侧各挖一个 14px 半圆（`::before/::after`）
- 下半是 `label - value` 对齐行，底部一对按钮（次要 ghost / 主要 solid）
- 用在：快递代取、外卖代收、预约回执

### P3 数据型 Dashboard
- 顶部 KPI 大数字（29px，`tabular-nums`）
- SVG 折线区（渐变填充 + 圆点描边），viewBox 300×46
- 3 个指标卡并列：数值 + 单位 + 状态标签（正常=绿 / 偏高=金）
- 用在：健康档案、健康报告

### P4 卡片流 Stream
- 一卡一项：左侧 44px 圆角图标块 → 中间标题+副文案+占比条 → 右侧金额/价格
- 占比条说明"这一项占总额多少"，是对比型信息
- 房源变体：通栏 104px 大图卡 + 左上类型角标 + 左下价格 + 右下面积楼层 + 三个核验标签
- 用在：缴费账单、房屋租售

### P5 设备型 Device
- `conic-gradient` 状态环（134px），内嵌白圆遮罩，环内是「剩余时间」
- 环下是设备名 + 计费规则 + 一对操作按钮
- 用在：共享雨伞、共享充电宝、维修工具

---

## 四、统一的「沉浸头」PageHero

所有服务页顶部统一为一块渐变头，变量只有两个：`--h1/--h2` 主题色 + 一个 KPI。

| 页面 | 主色 | KPI |
|---|---|---|
| 缴费代办 | 琥珀 `#F2A93B→#A85A08` | 本期应缴合计 ¥161.00 |
| 快递代收 | 青绿 `#12A08A→#0A6153` | 2 件在库 |
| 房屋租售 | 靛蓝 `#5B54C9→#322C88` | 4 套在挂 |
| 健康档案 | 湖蓝 `#0E8F9E→#0A5A66` | 128 mmHg |
| 共享设备 | 青绿 `#12A08A→#0A6153` | 6 把可借 |
| 预约向导 | 政务蓝 `#2E6BE0→#153F9B` | 服务名 + 0 元预约 |

结构：状态条 → 返回/标题/右侧动作 → KPI 行（大数字 + 两行解释 + 右侧胶囊标签）。
正文用 `margin-top:-30px` 压上来，形成"内容卡压在头图上"的层次 —— 与首页同一套语言。

---

## 五、同时删掉的东西

**每页尾部的「更多入口」列表卡全部删除。** 那些入口本身没错，但它们让 4 个不同页面有了同一个尾巴。
需要保留的入口改由「沉浸头的右侧动作」承担（如房源页右上「求租登记」、快递页右上「存放点」）。

---

## 六、落地到小程序时

| 骨架 | 小程序实现要点 |
|---|---|
| P1 向导 | 单页 + `step` 状态，不要用多个页面（避免返回栈混乱）；浮动条用 `position:fixed` + `padding-bottom` 占位 |
| P2 票据 | 齿孔用 `::before/::after` 圆 + 页面同色遮罩；取件码 `font-feature-settings:'tnum'` |
| P3 看板 | 折线用 `canvas` 或纯 `<view>` 折线，不要引图表库（包体积） |
| P4 卡片流 | 占比条用 `linear-gradient` 单条即可，不必组件化 |
| P5 设备环 | `conic-gradient` 在 iOS 微信需真机验证；兜底用 `canvas` 画环 |

组件规格页在 demo 右上的「🎨 组件库 → 6 · 页面原型」。
