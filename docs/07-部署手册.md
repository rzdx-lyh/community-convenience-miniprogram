# 07 · 云开发环境部署手册

> 适用：社区便民微信小程序 · 后端（微信云开发：云函数 + 云数据库 + 云存储）
> 对应契约：`contracts/api-contract.md` v1.2 / `contracts/db-schema.md` v1.2 / CR-012
> 前置：已在 `feature/backend` 分支完成开发，且本地 `node scripts/selftest.mjs` 全绿（138/138）
> 执行人：运维 / PM（后端工程师不执行 git，代码由 lead 统一提交）

## 0. 部署顺序总览（照着做即可）

```
① 建云环境 → ② 建 8 个集合 → ③ 建索引（users.accountId 唯一索引必建）
→ ④ 导入种子数据 → ⑤ 配环境变量 → ⑥ 打包并上传 8 个云函数
→ ⑦ 真环境冒烟 → ⑧ 10-23 重跑种子并确认紧急通知有效条数 > 0
```

## 1. 集合创建清单（8 个，与 db-schema v1.2 一一对应）

云开发控制台 → 数据库 →「+」新建集合。**集合名必须完全一致**（大小写敏感）：

| # | 集合名 | 用途 | 关联云函数 |
| :-: | --- | --- | --- |
| 1 | `users` | 用户档案与角色（含 `accountId`） | auth / user |
| 2 | `workorders` | 报修工单 | workorder |
| 3 | `notices` | 通知 / 活动 / **紧急通知** | notice |
| 4 | `phonebook` | 便民电话簿 | phonebook |
| 5 | `qa_feedback` | AI 问答反馈（有用/无用） | qa |
| 6 | `qa_sessions` | AI 多轮会话 | qa |
| 7 | `circle_post` | 社区圈子帖（只读数据源） | circle |
| 8 | `service_category` | 四类服务宫格导航 | service |

> ⚠ 知识库 **不是集合**：`cloudfunctions/shared/kb/kb.json` 随云函数代码部署，重新上传即生效。

### 1.1 数据权限（安全规则）

全部集合设为**「所有用户不可读写」**，读写只走云函数（架构设计 §7 硬规则）。
控制台路径：数据库 → 集合 →「权限设置」→ 自定义安全规则 → 选择「仅管理端可读写」。

## 2. 索引清单（必建 1 个 + 建议 3 个）

### 2.1 【必建】`users.accountId` 唯一索引

不建的后果：并发下两个用户可能拿到同一个社区账号，产生脏数据（架构设计风险 R-E）。

控制台路径：
`云开发控制台 → 数据库 → users 集合 → 索引管理 → 新建索引`

| 项 | 值 |
| --- | --- |
| 索引名称 | `accountId_unique`（自定义） |
| 字段 | `accountId` · 升序（ASC） |
| **是否唯一** | **是（唯一）** |

### 2.2 【建议】性能索引（演示级数据量可后补，出现慢查询再建）

| 集合 | 索引字段 | 用途 |
| --- | --- | --- |
| `notices` | `status + publishAt`（降序）、`type + endAt` | 列表分页、`urgentLatest` 有效期判定 |
| `circle_post` | `status + publishAt`（降序）、`type + status + publishAt`、`tags` | 圈子列表与筛选 |
| `service_category` | `key`（唯一）、`status + sort` | 宫格取数 |
| `workorders` | `status + createdAt`（降序）、`_openid` | 工单列表与隔离 |
| `qa_sessions` | `_openid + sessionId`（唯一）、`updatedAt` | 会话读写与过期清理 |

## 3. 导入种子数据

```bash
node scripts/seed.mjs      # 生成 scripts/seed-data.json（紧急通知用相对时间，永不过期）
```

控制台路径：`云开发控制台 → 数据库 → 集合 → 导入`
（或「数据库 → 导入/导出 → 导入」，选择 JSON，冲突处理选「Insert」）

| 集合 | 选择文件 | 条数 |
| --- | --- | --- |
| `users` | seed-data.json 的 `users` 数组 | 4（含 1 个 `accountId` 为空的懒迁移演示账号，可删） |
| `workorders` | `workorders` 数组 | 3 |
| `notices` | `notices` 数组 | 7（含 3 条 `type=urgent`） |
| `phonebook` | `phonebook` 数组 | 11（含 emergency 3 条：110 / 119 / 120） |
| `circle_post` | `circle_post` 数组 | 8（road 3 / notice 3 / activity 2） |
| `service_category` | `service_category` 数组 | 4（含内嵌 items，共 10 个子项） |

> `qa_feedback` / `qa_sessions` **不需要导入**（运行时产生）。
> ⚠ **占位号替换范围（CR-015-a / CR-016，口径以此为准）**：`phonebook` 共 11 条，分两类，**不要按"整体替换"理解**：
> - **可替换 8 条**（`020-8888xxxx` 段社区服务号）：物业服务中心、社区居委会、社区卫生服务站、自来水供水热线、供电服务热线、燃气服务热线、开锁服务、社区养老服务中心。真环境替换为各社区实际号码。
> - ⛔ **严禁替换 3 条**：`110` / `119` / `120` —— 国家公开紧急号码，是**真号码**，且印在紧急求助安全话术正文里（「火警 119 ｜ 报警 110 ｜ 急救 120」）。换掉会导致居民照话术拨打错号，**在最后一公里推翻 CR-012 整条护栏**。
>
> ⛔ **口径禁令（CR-016）**：任何文档、任何环节**不得再写"整体替换"**——这四个字到运维手里会被读成 11 条全换。一律写"8 条占位号可替换，110/119/120 严禁替换"。
>
> 改号有连带引用，**必须同步改**：
> - 社区养老服务中心 `020-88880000`：`service_category` 助浴项与知识库 `kb.json` 同步引用
> - 社区卫生服务站 `020-88885555`：前端 mock `MOCK_PHONEBOOK` 同步引用（曾误写为虚构号段 `020-87651120`，已修正）
>
> 改号唯一路径（CR-014-a）：改 `cloudfunctions/shared/hotline.js` → 重跑 `seed.mjs` → 重新导入 → 通知前端同步 mock → 跑 `selftest.mjs` 双向断言。
> ⛔ **禁止在云控制台手工编辑 phonebook 号码**：手工一改，代码真源与库里数据各说一套，所有一致性断言全部失效。
>
> ⛔ **禁止在云控制台手工编辑 `phonebook` 的号码**（CR-014-a）：号码真源是 `cloudfunctions/shared/hotline.js` 常量，集合只是 seed 的派生物。手工一改，代码真源与库里数据各说一套——安全话术让打 A 号、便民电话簿显示 B 号，评委现场照号拨打就能发现，且一致性自测断言全部失效。
> 改号唯一路径：改 `shared/hotline.js` → 重跑 `node scripts/seed.mjs` → 重新导入 → 通知前端同步 mock → 跑 `node scripts/selftest.mjs`。

## 4. 环境变量（云函数）

控制台路径：`云开发控制台 → 云函数 → 函数列表 → 任一函数 → 配置 → 环境变量`（**按函数逐个配置，或新建环境级配置**）

| 变量 | 用途 | 是否必配 | 缺失后果 |
| --- | --- | --- | --- |
| `DEEPSEEK_API_KEY` | DeepSeek deepseek-chat 调用鉴权 | 演示建议配 | 缺省 → `qa:ask` 降级（回知识库原文/兜底话术），工单 AI 摘要用原文截断，**接口全部可用，不报错** |
| `TCB_ENV` | 云开发环境 ID | 建议配 | 缺省时 `cloud.init` 用 `DYNAMIC_CURRENT_ENV`（当前环境），一般不报错 |
| `PHONE_AES_KEY` | 手机号 AES-256-GCM 密钥（64 位 hex） | **真环境必配** | 缺省 → 回落到本地开发密钥并打告警，等同明文，评审会看到告警日志 |
| `SUBSCRIBE_TEMPLATE_WORKORDER_DONE` | 工单完成订阅消息模板 ID | 可选 | 缺省 → 降级为日志，工单流程不受影响 |
| ~~`CCF_FORCE_MOCK`~~ | **本地 mock 强制开关** | **真环境禁止配置** | 若设为 `1`，云函数会走内存 mock，读写不到真数据库 |
| ~~`CCF_MOCK_NO_SEED`~~ | 本地是否载入种子 | **真环境禁止配置** | 同上 |

生成手机号密钥（本地执行一次，把输出粘到控制台，**不要写进代码或提交**）：

```bash
openssl rand -hex 32
```

> 🔒 铁律：以上变量只存在于控制台或本地 shell，**永不写入代码、文档或 git**；提交前自检 `grep -rn "sk-" cloudfunctions scripts docs`。

## 7. 演示前验收动作（10-23 必做）

> 按顺序做，**第 1 项没做完后面全都白做**。第 1 项的联调必须在 **10-23 之前**完成，不能留到当天。

### 7.0 【第 1 项】关掉 mock 开关 + 真环境联调（前置条件）

```bash
# miniprogram/config/env.ts
USE_MOCK: false,      // ← 演示/联调必须 false
CLOUD_ENV_ID: 'xxx',  // ← 填真实云环境 ID
```

**为什么排第 1**：`USE_MOCK: true` 时前端走内存 mock，8 个云函数**全部不参与**——CR-012 安全护栏、真实号码库、真实工单流在演示现场全部"隐身"，后端交付等于没做。

### 7.0.1 后端前置条件（be-engineer 逐项核查，缺一即失败）

| # | 前置条件 | 不做会怎样 |
| :-: | --- | --- |
| 1 | 云开发环境已开通，**环境 ID 已填进 `CLOUD_ENV_ID`** | `wx.cloud.init` 全部失败 |
| 2 | 8 个云函数已由 `npm run build:cf && 逐个上传部署` 上传 | 前端拿到「云函数不存在」 |
| 3 | 8 个集合已在云控制台建好（`users` / `notice` / `workorder` / `phonebook` / `circle` / `service_category` / `qa_session` / `feedback`） | 读写报「collection not exists」 |
| 4 | ⚠️ **`users.accountId` 唯一索引必须在导入种子「之前」建** | 导入后建会撞重复键失败，只能删库重来 |
| 5 | `node scripts/seed.mjs` 生成 `scripts/seed-data.json` 并**导入一次**（**只导一次；重复导入会让第 4 条的唯一索引建不上**） | 首页空态 |
| 6 | 集合权限按 `db-schema.md` 设好（默认值「仅创建者可读写」会导致 emergency 读不到） | 权限拒绝 |
| 7 | 云函数环境变量已配：`DEEPSEEK_API_KEY` / `PHONE_AES_KEY` / `PHONE_RESERVE` / `SELFTEST_MODE=false`；⛔ **绝不能设 `CCF_FORCE_MOCK=1`** | 写不进真库，静默走 mock |

### 7.0.2 联调 = 逐层拆 mock（6 层，按 CR-018 分层口径）

| # | 层 | 自测态 | 真机态 | 换层风险 |
| :-: | --- | :-: | --- | :--- |
| 1 | 云函数代码 | ✅ 原件真跑 | 原件 | 无 |
| 2 | 持久层 | ❌ 内存库 + seed | 云数据库 | **索引/集合/权限未建 → 真机报错** |
| 3 | 用户身份 | ❌ 注入 openid | `getWXContext` | 权限判断差异 |
| 4 | 大模型 | ❌ 未调用（走降级） | deepseek-chat | **真实回答 / 8s 超时 / 降级阈值** |
| 5 | 内容安全 | ❌ 测试违禁词 | `msgSecCheck` | 需配置，未配则拦截失效 |
| 6 | 订阅消息 | ❌ 仅记日志 | 真发送 | 模板 ID 需申请 |

**联调验收（硬门槛）**：置 false 后重跑第 6 节真环境冒烟 7 项，全绿才算联调通过；其中 **CR-012 端到端（问「胸痛怎么办」→ 出现 120）不可省**——它是唯一能同时验证「云函数通 + 持久层通 + 护栏通 + 渲染通」的路径。若不通过，改回 `true` 保底，**不要带着 false 上场**。

⛔ 联调未通过 = 未验收，此时**不允许**进入 7.1。

### 7.1 重跑 seed（紧急通知过期风险 R-B）

```bash
node scripts/seed.mjs
```

确认脚本末尾打印的**「紧急通知 3 条，其中当前有效 N 条」中 N > 0**（当前为 3）。

原因：`notice:urgentLatest` 会过滤 `endAt < now` 的已过期紧急通知（风险 R-B）。
种子全部用相对时间生成（`now-Nh` / `now+Nd`），只要**重跑脚本**就不会过期；**直接复用旧的 seed-data.json 则有过期风险**。

同步确认：`circle:list` 非空（8 条）、`service:list` 返回 4 条分类、`phonebook:list` 返回 11 条且其中 `emergency` 分类 = **3 条（110 报警求助 / 119 火警 / 120 急救）**。

## 8. 回滚与故障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 全部接口报「云函数不存在」 | 函数未上传，或调用用了 `name:'资源:动作'` 冒号形态 | 走形态 B：`name='<资源>'` + `data.action='<动作>'` |
| `qa:ask` 一律回知识库原文 | 无 `DEEPSEEK_API_KEY`（正常降级）或 Key 失效 | 配 Key；无 Key 也可演示，属设计内降级 |
| 首页紧急区空态 | `seed-data.json` 过期未重跑 | 重跑 `node scripts/seed.mjs` 并重新导入 |
| 宫格白屏 | `service:list` 失败 | 后端已保证异常时返回 `{code:0,list:[]}`，前端应回退 `config/service-grid.ts`；同时检查 `service_category` 是否已导入 |
| 社区账号报「已被使用」撞号 | `users.accountId` 唯一索引未建 | 补建唯一索引 |
| 云函数日志出现「使用本地开发密钥」 | 未配 `PHONE_AES_KEY` | 第 4 节配置 |
| 数据写不进真库 | 误配 `CCF_FORCE_MOCK=1` | 删除该环境变量 |
| 界面顶部出现「演示数据模式」标识 | `USE_MOCK` 仍为 true | 完成 7.0 后置 false |

## 9. 答辩口径（评委提问预案）

### 9.1 「你们这个电话打得通吗？」

> 电话簿 11 条分两类：`110 / 119 / 120` 是**国家公开紧急号码**，真实可拨，任何环境都不改；其余 8 条（`020-8888xxxx` 段）是**演示环境占位数据**，真实部署时由各社区替换为本单位实际号码。我们把号码做成了**配置化数据 + 单一真源**（`cloudfunctions/shared/hotline.js`），而不是写死在页面里，就是为了社区接入时零改代码——这也是为什么部署手册里对它有一条「严禁整体替换」的红线。

⚠ 口径纪律（CR-016）：**不要说「部署时整体替换」**，会被听成 11 条全换。说「可替换 8 条 / 严禁替换 3 条」。

### 9.2 「AI 说的准不准？出了事谁负责？」

> AI 助手有**前置安全护栏**（CR-012）：涉医、涉法、紧急求助三类问题在**调大模型之前**就被拦截，直接返回固定安全话术（如「胸痛」→ 引导拨打 120），不经过模型生成。非风险问题走知识库 + 大模型，回答尾部固定注入「AI 生成仅供参考」，且答案附带来源出处可追溯。无 API Key 时自动降级为知识库原文，属于设计内降级。

⚠️ **若评委问「你们接了真模型吗」**：如实说——**演示环境未接真实大模型 API**，当前走的是**本地知识库检索降级**，这是产品设计的**三级降级**中的一级：
① 前置安全护栏（高风险问题不进模型）→ ② 知识库检索 + 大模型改写 → ③ 无 Key / 超时 / 服务不可用时**退回知识库原文**。
第 ③ 级不是"没做完"，而是**社区场景的容错底线**：断网、欠费、服务抖动时居民照样问得到答案。降级路径自给自足，**不依赖它正在降级的那个通道**（CR-018-b）。
⛔ 但**不要撒谎说接了真模型**——评委追问两句就会穿帮，反而丢分。

### 9.3 「这些数据是真的吗？」

> 演示环境是种子数据（`scripts/seed.mjs` 一键导入，8 个集合）。产品本身是**数据驱动**的：公告、帖子、服务分类、电话簿全部来自云数据库，前端不写死任何业务内容，社区接入只需导自己的数据。

## 10. 验收口径（CR-017-b，全队适用）

> **所有契约一致性结论、接口验收、端到端断言，必须在 `USE_MOCK = false` 通道下取得；mock 通道下的「全绿」不构成任何契约验收证据。**
> 凡出现「xxx 条测试全绿」的结论，**必须同时说明跑在哪个通道**；未说明通道的，一律视为无效验收。

理由：mock 返回的是前端自己的内存副本（CR-013/CR-015/CR-016/CR-017 四次事故的共同根因——**用副本证明原件**），只能证明渲染逻辑正确，证明不了云函数分发、错误码、降级字段、安全护栏、种子数据中的任何一项。

因此本手册第 6 节真环境冒烟 7 项，是**唯一有效**的验收动作；`npm run test`（vitest）与 `npm run selftest`（后端自测）是**回归网**，不是验收证据。
