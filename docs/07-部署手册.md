# 07 · 云开发环境部署手册

> 适用：社区便民微信小程序 · 后端（微信云开发：云函数 + 云数据库 + 云存储）
> 对应契约：`contracts/api-contract.md` v1.2 / `contracts/db-schema.md` v1.2 / CR-012
> 前置：已在 `feature/backend` 分支完成开发，且本地 `node scripts/selftest.mjs` 全绿（138/138）
> 执行人：运维 / PM（后端工程师不执行 git，代码由 lead 统一提交）

---

## 0. 部署顺序总览（照着做即可）

```
① 建云环境 → ② 建 8 个集合 → ③ 建索引（users.accountId 唯一索引必建）
→ ④ 导入种子数据 → ⑤ 配环境变量 → ⑥ 打包并上传 8 个云函数
→ ⑦ 真环境冒烟 → ⑧ 10-23 重跑种子并确认紧急通知有效条数 > 0
```

---

## 1. 集合创建清单（8 个，与 db-schema v1.2 一一对应）

云开发控制台 → 数据库 →「+」新建集合。**集合名必须完全一致**（大小写敏感）：

| # | 集合名 | 用途 | 关联云函数 |
| :-: | --- | --- | --- |
| 1 | `users` | 用户档案与角色（含 `accountId`） | auth / user |
| 2 | `workorders` | 报修工单 | workorder |
| 3 | `notices` | 通知 / 活动 / **紧急通知** | notice |
| 4 | `phonebook` | 便民电话簿 | phonebook |
| 5 | `qa_feedback` | AI 问答反馈（有用/无用） | qa |
| 6 | `qa_sessions` | AI 多轮会话 | qa |
| 7 | `circle_post` | 社区圈子帖（只读数据源） | circle |
| 8 | `service_category` | 四类服务宫格导航 | service |

> ⚠ 知识库 **不是集合**：`cloudfunctions/shared/kb/kb.json` 随云函数代码部署，重新上传即生效。

### 1.1 数据权限（安全规则）

全部集合设为**「所有用户不可读写」**，读写只走云函数（架构设计 §7 硬规则）。
控制台路径：数据库 → 集合 →「权限设置」→ 自定义安全规则 → 选择「仅管理端可读写」。

## 2. 索引清单（必建 1 个 + 建议 3 个）

### 2.1 【必建】`users.accountId` 唯一索引

不建的后果：并发下两个用户可能拿到同一个社区账号，产生脏数据（架构设计风险 R-E）。

控制台路径：
`云开发控制台 → 数据库 → users 集合 → 索引管理 → 新建索引`

| 项 | 值 |
| --- | --- |
| 索引名称 | `accountId_unique`（自定义） |
| 字段 | `accountId` · 升序（ASC） |
| **是否唯一** | **是（唯一）** |

### 2.2 【建议】性能索引（演示级数据量可后补，出现慢查询再建）

| 集合 | 索引字段 | 用途 |
| --- | --- | --- |
| `notices` | `status + publishAt`（降序）、`type + endAt` | 列表分页、`urgentLatest` 有效期判定 |
| `circle_post` | `status + publishAt`（降序）、`type + status + publishAt`、`tags` | 圈子列表与筛选 |
| `service_category` | `key`（唯一）、`status + sort` | 宫格取数 |
| `workorders` | `status + createdAt`（降序）、`_openid` | 工单列表与隔离 |
| `qa_sessions` | `_openid + sessionId`（唯一）、`updatedAt` | 会话读写与过期清理 |

## 4. 环境变量（云函数）

控制台路径：`云开发控制台 → 云函数 → 函数列表 → 任一函数 → 配置 → 环境变量`（**按函数逐个配置，或新建环境级配置**）

| 变量 | 用途 | 是否必配 | 缺失后果 |
| --- | --- | --- | --- |
| `DEEPSEEK_API_KEY` | DeepSeek deepseek-chat 调用鉴权 | 演示建议配 | 缺省 → `qa:ask` 降级（回知识库原文/兜底话术），工单 AI 摘要用原文截断，**接口全部可用，不报错** |
| `TCB_ENV` | 云开发环境 ID | 建议配 | 缺省时 `cloud.init` 用 `DYNAMIC_CURRENT_ENV`（当前环境），一般不报错 |
| `PHONE_AES_KEY` | 手机号 AES-256-GCM 密钥（64 位 hex） | **真环境必配** | 缺省 → 回落到本地开发密钥并打告警，等同明文，评审会看到告警日志 |
| `SUBSCRIBE_TEMPLATE_WORKORDER_DONE` | 工单完成订阅消息模板 ID | 可选 | 缺省 → 降级为日志，工单流程不受影响 |
| ~~`CCF_FORCE_MOCK`~~ | **本地 mock 强制开关** | **真环境禁止配置** | 若设为 `1`，云函数会走内存 mock，读写不到真数据库 |
| ~~`CCF_MOCK_NO_SEED`~~ | 本地是否载入种子 | **真环境禁止配置** | 同上 |

生成手机号密钥（本地执行一次，把输出粘到控制台，**不要写进代码或提交**）：

```bash
openssl rand -hex 32
```

> 🔒 铁律：以上变量只存在于控制台或本地 shell，**永不写入代码、文档或 git**；提交前自检 `grep -rn "sk-" cloudfunctions scripts docs`。

## 5. 云函数上传

### 5.1 打包（把 shared 复制进各函数目录，上传前必做）

```bash
node scripts/build-cf.mjs           # 8 个函数各自内嵌一份 shared/
node scripts/build-cf.mjs --clean   # 上传完成后清理本地副本（产物不要提交 git）
```

### 5.2 上传

> ⚠ **上传前检查点**：先跑 `node scripts/build-cf.mjs` 并确认 **exit 0**，再逐个上传；若 exit 非 0 说明 `shared/` 未打包，上传后函数会报模块找不到。
> （踩过的坑：`fs.cpSync` 在 Node v22/Windows 下会直接段错误，打包静默失败、8 个函数全废；脚本已改为手写递归复制，但仍以 exit 0 为准。）

微信开发者工具 → 云开发 → 云函数 → 右键 `cloudfunctions/<资源>` →「上传并部署：云端安装依赖（不上传 node_modules）」，逐个上传 8 个：

`auth` · `user` · `workorder` · `notice` · `circle` · `service` · `phonebook` · `qa`

### 5.3 超时配置（已写入各 `config.json`，上传后可在控制台复核）

| 函数 | timeout | 说明 |
| --- | :-: | --- |
| `qa` | **60s** | 含大模型调用（HTTP 超时 8s） |
| 其余 7 个 | **20s** | 无 AI 调用 |

`config.json` 的 `permissions.openapi` 也已配好：
`qa` / `workorder` 需 `security.msgSecCheck`，`workorder` / `notice` 需 `subscribeMessage.send`。

## 6. 真环境冒烟（上传后必做）

用小程序真机/模拟器登录一次（`auth:login` 会自动建档），然后逐项确认：

| # | 验证 | 期望 |
| :-: | --- | --- |
| 1 | 首页紧急区 | 显示 3 条紧急通知轮播（停水 / 道路检修 / 电梯年检） |
| 2 | 首页四类宫格 | 4 格渲染，8 个子项点击全部可达（0 个「建设中」） |
| 3 | 社区圈子 | 列表 8 条；「路况」Tab ≥3 条；官方徽标出现在 `阳光社区居委会` 帖子 |
| 4 | 我的 → 社区账号 | 有值（`linju_xxxxxx`），可改；改成他人账号提示「社区账号已被使用，换一个试试」 |
| 5 | 报修创建 | 提交成功并返回 AI 摘要（无 Key 时为原文截断兜底） |
| 6 | AI 助手 | 提问「家里水管漏水怎么报修？」有答案 + 来源；提问「我爸突然胸痛出汗」返回 **CR-012 安全话术** + `_riskLevel=medical` |
| 7 | 便民电话簿 | 11 条；紧急求助面板能取到 **110 / 119 / 120** 三条（emergency 分类共 3 条） |

> ⚠ **演示通道检查**：`miniprogram/config/env.ts` 的 `ENV.USE_MOCK` 演示前必须为 **false**，否则走前端内存 mock（不经过云函数），CR-012 等后端能力现场演示不出来。

## 7. 演示前验收动作（10-23 必做）

```bash
node scripts/seed.mjs
```

确认脚本末尾打印的**「紧急通知 3 条，其中当前有效 N 条」中 N > 0**（当前为 3）。

原因：`notice:urgentLatest` 会过滤 `endAt < now` 的已过期紧急通知（风险 R-B）。
种子全部用相对时间生成（`now-Nh` / `now+Nd`），只要**重跑脚本**就不会过期；**直接复用旧的 seed-data.json 则有过期风险**。

同步确认：`circle:list` 非空（8 条）、`service:list` 返回 4 条分类、`phonebook:list` 返回 11 条且其中 `emergency` 分类 = **3 条（110 报警求助 / 119 火警 / 120 急救）**。

## 8. 回滚与故障速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 全部接口报「云函数不存在」 | 函数未上传，或调用用了 `name:'资源:动作'` 冒号形态 | 走形态 B：`name='<资源>'` + `data.action='<动作>'` |
| `qa:ask` 一律回知识库原文 | 无 `DEEPSEEK_API_KEY`（正常降级）或 Key 失效 | 配 Key；无 Key 也可演示，属设计内降级 |
| 首页紧急区空态 | `seed-data.json` 过期未重跑 | 重跑 `node scripts/seed.mjs` 并重新导入 |
| 宫格白屏 | `service:list` 失败 | 后端已保证异常时返回 `{code:0,list:[]}`，前端应回退 `config/service-grid.ts`；同时检查 `service_category` 是否已导入 |
| 社区账号报「已被使用」撞号 | `users.accountId` 唯一索引未建 | 补建唯一索引 |
| 云函数日志出现「使用本地开发密钥」 | 未配 `PHONE_AES_KEY` | 第 4 节配置 |
| 数据写不进真库 | 误配 `CCF_FORCE_MOCK=1` | 删除该环境变量 |
