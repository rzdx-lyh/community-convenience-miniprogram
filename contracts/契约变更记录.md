## CR-001 · qa 分组补齐多轮会话能力

| 项 | 内容 |
| --- | --- |
| **日期** | 2026-10-13 |
| **提出人** | 主分支 owner（经 AI Agent 工程评审发现） |
| **变更内容** | `qa:ask` 入参增加 `sessionId?: string`；出参增加 `sessionId: string`；明确多轮上下文保留规则（最近 3 轮 / 单条 ≤300 字 / 总上下文 ≤2000 tokens / 会话 2 小时过期） |
| **原因** | v1.0 的 `qa:ask` 是无状态接口，无 sessionId 也无会话存储。但既有测试用例要求多轮：<br>• `07-测试工程师-skill.md` **TC-44**「多轮上下文连贯」<br>• 同文件 **AIQ-20**「会话内上下文一致，不混乱」<br>→ **这些用例在 v1.0 下不可能通过**，属于契约缺失导致的必然验收失败 |
| **影响面** | 前端 A：AI 助手页需维护并回传 `sessionId`<br>后端 B：BE-6 需实现会话读写与上下文压缩<br>测试：现有用例可正常执行 |
| **向后兼容** | ✅ 兼容。`sessionId` 为可选入参，缺省时服务端自动新建并返回，老调用不会 400 |
| **同步状态** | `api-contract.md` ✅ ｜ `db-schema.md` ✅（`qa_sessions`） ｜ `task-cards.md` ⬜ 待补 BE-6 验收项 ｜ 测试用例 ⬜ 无需改，本变更正是为满足既有用例 |

## CR-002 · 知识库落地位置定稿

| 项 | 内容 |
| --- | --- |
| **日期** | 2026-10-13 |
| **提出人** | 主分支 owner |
| **变更内容** | 定稿为 `cloudfunctions/shared/kb/kb.json`（代码内置 JSON 文件，**不是数据库集合**）；数据结构含 `id/title/content/category/keywords[]/synonyms[]`；检索为关键词 + 同义词打分，未命中阈值 < 1.0 直接兜底；`qa_feedback` 集合**收敛为纯反馈表** |
| **原因** | v1.0 存在**三方矛盾**：<br>• `db-schema.md` 集合清单里**根本没有知识库**<br>• `04-架构师-skill.md`（L637-650）假设塞进 `qa_feedback` 并用 `type` 字段区分 `qa_doc`/`feedback`/`qa_log`<br>• `06-后端工程师-skill.md`（L41）称"知识库 JSON 化"<br>→ 后端开工必然卡壳，无法判断照哪份实现 |

| **影响面** | 后端 B：BE-7 按 JSON 实现<br>测试：知识库检索用例可正常设计 |
| **向后兼容** | ⚠️ 与 `04-架构师-skill.md` 早期草案**不兼容**，该草案章节已标注废弃 |
| **同步状态** | `api-contract.md` ✅（末节附录） ｜ `db-schema.md` ✅ ｜ `04-架构师-skill.md` ⬜ 待标注废弃 ｜ `06-后端工程师-skill.md` ✅ 原本即 JSON 方案 |
