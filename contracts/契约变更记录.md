## CR-006 · 新增 notice:urgentLatest（首页紧急区专用接口）

| 项                       | 内容                                                                                                                                                                                                                                                                                                                                                       |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **日期**                  | 2026-10-13                                                                                                                                                                                                                                                                                                                                               |
| **提出人**                 | 架构师（在「新增专用接口」与「notice:list 加 filter」**二选一**中的裁决）                                                                                                                                                                                                                                                                                                         |
| **变更内容**                | 新增动作 `notice:urgentLatest`：入参 `{ limit?: number }`（默认 5、上限 10）；出参 `{ list: Notice[], total: number }`                                                                                                                                                                                                                                                    |
| **选型理由（二选一 → 选新增专用接口）** | 1. **职责不同**：`notice:list` 是分页浏览语义（翻页看完），紧急区是「取当前有效 TopN 做轮播卡片」语义，不需要 `page`、需要有效期过滤 + `level` 复合排序。揉在一起会让同一接口服务两种调用形态<br />2. **冷启动**：云函数首调冷启动 1~3s（架构师规范 §12 坑 #2），首屏调用轮次越少越好；专用接口一次返回 N 条，省掉前端侧过滤<br />3. **工期**：后端增量仅 1 个 action 分支（0.5 天），不触碰任何既有代码路径<br />4. **降级通道内置**：`notice:list({type:'urgent', pageSize:5})` 能力等价，可作 `urgentLatest` 未就绪时的临时替代 |
| **关键协议**                | ① 筛选 `status=published AND type=urgent AND startAt<=now(空跳过) AND endAt>=now(空跳过)`；② 排序 `level`(critical3>high2>normal1) → `startAt` → `publishAt` 降序；③ **空数据返回 `{code:0,msg:'ok',data:{list:[],total:0}}`，不是 404**                                                                                                                                       |
| **向后兼容**                | ✅ 纯新增动作，既有接口零改动                                                                                                                                                                                                                                                                                                                                          |
| **影响面**                 | 前端 FE-11（首页紧急区 + 3s 轮播，空态文案「暂无紧急通知，社区运行正常」）<br />后端 BE-9<br />测试：新增「过期不返回」「版面 데이터为空返回空数组」用例                                                                                                                                                                                                                                                              |
