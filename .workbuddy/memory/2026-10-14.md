## 补充（03:40）· 白屏两连 + 编译产物污染工具链

### 用户遇到的白屏（连续两次，都已修）
1. 第一次：`components/mock-banner/index.js is not defined` —— 组件源码写成 `.ts`，用户的 DevTools（Stable 2.02.20）对**组件目录**的 TS 编译插件不生效，运行时 require 不到 .js。
2. 第二次（改成 .js 后仍报）：`Component is not found in path "components/mock-banner/index"` —— 组件在运行时仍注册失败。
→ **处置：不再与它纠缠**。从 index/assistant/profile 三页移除 `<mock-banner />` 与 usingComponents，删除 `components/mock-banner/`，回退 .gitignore 例外（commit `14a5fec`）。
→ **结论：本项目不要用自定义组件做非必需装饰**。用户环境 DevTools 版本对组件的 TS/JS 混合编译不可靠，而首页渲染是刚需。横幅以后要做就**内联进页面 wxml**（app.wxss 放样式 + 页面 data 绑 wx:if），不走自定义组件。

### 根因（比白屏本身更重要，跨会话有效）
**微信开发者工具会把 `miniprogram/**/*.ts` 编译成同名 `.js`，而 Vite 的默认解析顺序是 `.js` 优先于 `.ts`** → vitest 会抽到编译产物而非 TS 源码。表现为：
- 测试报 `xxx is not a function`（抽到空/旧模块），一度 73 个测试崩；
- eslint lint 编译产物，报 18 个 `'Page' is not defined` 假错误。
**修复（已做，永久生效）**：
- `vitest.config.mts` 加 `resolve.extensions: ['.ts', '.tsx', '.mts', '.js', ...]`，让 .ts 优先。
- `eslint.config.mjs` 的 ignores 加 `miniprogram/**/*.js`。
- 验证方式（探针法，比删文件更可信）：在旁边放一个 `throw new Error()` 的 `.js`，测试仍 9/9 通过才说明 .ts 真的优先。
→ **教训：删掉 .js 只是治症状，改解析顺序才是治根因**；用户每次点「编译」都会重新生成 .js，只有配置层修复才不会复发。
