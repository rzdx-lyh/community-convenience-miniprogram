## 14:00 · 修复线上 P0：云函数 `Cannot find module 'response'`

用户截图：模拟器点「提交预约」报
`errCode: -504002 functions execute fail | Error: Cannot find module 'response'`
堆栈 `at Object.<anonymous> (/var/user/index.js:2:15)`。

### 根因（重要，别误判成代码 bug）
**云端跑的是旧版 index.js**：写成裸模块名 `require('response')`，且旧包缺 `shared/`。
本地早已是 `require('./shared/response')`，本地 `require` 实测可加载 → **不是代码缺陷，是部署滞后**。
旁证：报错指向 `index.js:2`，而当前本地第 2 行是空行，第 5 行才是 require。

### 修复动作（可复用）
1. `node scripts/build-cf.mjs --clean` ← **只重建各函数下 shared/，不动 node_modules**
2. `cli cloud functions deploy --env <env> --names <8个> --project <根目录>`
   **不加 `--remote-npm-install`**
3. 判据：`filesCount=5846` / `packSize=6.7MB` = 带依赖；19 = 没带依赖
4. 验证：`cli cloud functions download --name workorder --path .tmp_dl` 拉回云端 →
   index.js 第 5 行确为 `./shared/response`、`shared/response.js` 在 → 本地 require 成功、main 是 function

### 同时实测确认的两件事
- **`config.json` 的 `timeout: 20` 完全不被 CLI 应用**，云端 `cloud functions info` 显示
  `timeout=3`、`runtime=Nodejs16.13` → 只能控制台逐个改 20s（这就是「配了 Key 还降级」的根因）。
- runtime 是 **Nodejs16.13**，`shared/ai.js` 用原生 `https.request` 所以没事；
  **若将来改成 `fetch` 会直接挂**（Node16 无全局 fetch）。这条要写进交接。

### 教训
`cloud-preflight.mjs` 只校验本地源码，**校验不到云端是不是旧版**。
以后改完 `cloudfunctions/**` 必须重新部署，并在回复里提醒「重新编译再试」。

### ★ 17:50 真根因：`shared/` 与云函数运行时目录重名（commit a1d4a85）

**前两次判断都错了**（先说"部署滞后"，再说"部署中间态"）。真正证据在报错栈：

```
at Object.<anonymous> (/var/user/index.js:5:15)
at /var/user/shared/function.js:8
```

`shared/function.js` **不在我们的代码包里**（grep 过 workorder/shared 和 node_modules，都没有）
→ 它是**微信云函数运行时注入到 `/var/user/shared/` 的入口包装**。
我们的副本目录也叫 `shared/` → 解压时被运行时目录覆盖 → response/db/auth 等全部消失。

**为什么前两次会被骗**：
- 本地 `require` 正常 → 以为不是代码问题
- `download` 拉云端产物 → `shared/` 16 文件齐全 → 以为不是上传问题
  （其实下载的是**部署包**，不是运行时解压后的目录）

**修法**：副本目录 `shared/` → **`lib/`**
- `build-cf.mjs` 目标改 lib
- 8 个 index.js 共 38 处 `require('./shared/` → `./lib/`
  （shared 内部都是 `./db` 同目录引用，改名零影响）
- preflight 加「禁止残留 shared/ 副本」硬检查
- 删掉 8 个函数下旧 shared/ 副本（源 `cloudfunctions/shared/` 保留不动）

**验证**：预检 3 绿 / 8 函数本地 main=function / 部署 5846×8 成功 /
云端产物顶层只有 lib、无 shared / 云端产物 require 成功 + lib/kb 深层也 OK。

**教训（写进规则）**：云函数共享目录**永远不要叫 shared**，
下划线前缀也不行（会被上传跳过）。用 `lib` / `common`。
`docs/07-bug清单.md` BUG-008 已改写为真实根因。
