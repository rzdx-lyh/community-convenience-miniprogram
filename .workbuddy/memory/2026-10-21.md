
## 12:55 · 修复真机布局错位（状态栏 + 底部安全区）

### 用户诉求
上传手机体验时显示区域错位。

### 根因（两处，都在小程序适配层）
1. **状态栏 `.sbar` 双重 padding 叠加**：`layout.wxss` 适配层给 `.sbar` 写了
   `min-height:48rpx + box-sizing:content-box + padding-top:env(safe-area-inset-top)`，
   而 22 个页面又用内联 `style="padding-top:{{statusBarHeight}}px"` 撑状态栏。
   content-box 下 padding 叠加在 min-height 上 → 不同机型 statusBarHeight 不同，
   状态栏条高度忽高忽低、内容错位。内联的 px 值本身是对的（getWindowInfo 返回物理 px）。
2. **底部 fixed 元素无 safe-area-inset-bottom**：`.fbar`/`.footbar`/`.fab2`/`.sheet`
   都是 `position:fixed;bottom:0`，iPhone 全面屏 home indicator 会盖住/贴死底条；
   `.page--fbar` 的 200rpx 留白也没算安全区，底条加高后重新盖内容。

### 修复（改生成器 scripts/gen-layout-wxss.mjs 后重跑，未手改生成物）
- `.sbar`/`.hd .sbar`/`.pgh .sbar`：`box-sizing:content-box` → `border-box`，
  padding 计入高度不再叠加（注释也更新了）。
- 底部：`.fbar/.footbar` padding-bottom 补 `env(safe-area-inset-bottom)`；
  `.fab2` bottom 补安全区；`.sheet` padding-bottom 补安全区；
  `.page--fbar` padding-bottom 从 200rpx 改 `calc(200rpx + env(...))`。
- 注意：只改 padding-bottom（不碰各元素原有横向 padding），避免覆盖 `.fbar` 的
  `18rpx 24rpx` 等简写。

### 验证
- gen-layout-wxss 重跑：601 规则 / 63110 字节。
- 310/310 测试通过；check-pages 无错；`cli preview` 编译通过（出二维码）。

## 13:25 · 抓到真机错位的真凶：生鲜页 `.ib` 与全局图标底座 `.ib` 撞名（用户模拟器截图实锤）

- 现象（用户截图「当日鲜菜」页）：商品卡里名称/规格被压成**一字一行竖排**（"土/鸡/蛋"），
  价格行挤在旁边。模拟器 iPhone 15 Pro Max 即可复现。
- 根因：`layout.wxss:48` 的全局 `.ib{width:80rpx;height:80rpx;display:flex;...}` 是**图标底座**
  （昨天日志记过「原型 `.ic` 底座改名 `.ib`」——改名后与生鲜原型自带的商品信息块 `.skc .ib` 撞名）。
  信息块被压成 80rpx 方块，减 padding 只剩 44rpx → 中文一字一行。
- 修复：`pages/service/fresh/index.wxml` 信息块 `.ib` → `.pib`（wxml 加注释说明）；
  `index.wxss` 补 `.skc .pib{padding:16rpx 18rpx 18rpx}` + `.pib .nm/.ds` 字号
  （原型带来的 `.skc .ib{padding}` 因改名失效，页面层补回）。
- 系统性扫描：全项目 `class="ib"` 用作信息块的只有生鲜一处（已改）；其余短类名命中多为
  `ic-map` 之类图标名误报，无第二个真实撞名。
- 验证：310/310 测试、check-pages 通过、cli preview 编译通过。
- 连同上午的修复（.sbar box-sizing、底部 safe-area），一起等用户真机复验。
- 教训（通用）：生成器做 `.ic`→`.ib` 这类全局改名时，必须 grep 原型里旧名是否已被用作其他语义。

## 23:55 · 用户三张截图反馈「页面显示错误」→ 修两处

### 问题 1：双状态栏（截图 1/2）
- 现象：真机/模拟器上系统真状态栏（23:45 + 灵动岛）下方又渲染一条原型假状态栏（08:42 ●●●）。

  是手机壳装饰，照搬进小程序就重复了（22 处 .sbar 全是装饰文本，已逐一核实无交互内容）。
- 修复：生成器 ADAPTER 加 `.sbar text{display:none}`，`.sbar` 只保留 spacer 职责
  （内联 padding-top=statusBarHeight 撑开，border-box 不叠加）。map 页右上的定位状态
  隐藏后仍有「重新定位」按钮入口，功能不受影响。

### 问题 2：AI 助手气泡显示 %E5 URL 编码（截图 3）
- 根因：ai-bar 跳转 `/pages/assistant/index?presetQuestion=<encodeURIComponent(q)>`，
  微信不保证自动解码 onLoad options，assistant 的 normalizePresetQuestion 没解码就显示/提问。
- 修复：normalizePresetQuestion 兜底解码一次——只在 /%[0-9A-Fa-f]{2}/ 命中时 decode，
  try/catch 保底，普通含 % 的中文（如「5% 怎么算」）不受影响。
- 测试：assistant.test.ts 加 3 个用例（编码解码 / 含 % 不误解 / 非法编码不抛错）。
- 验证：315/315 测试全过，check-pages 通过，cli preview 编译通过。
